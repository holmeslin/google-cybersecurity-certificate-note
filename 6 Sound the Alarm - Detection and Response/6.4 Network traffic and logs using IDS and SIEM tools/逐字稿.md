### The importance of logs 日誌的重要性

Devices produced data in the form of events.  
裝置以事件的形式產生資料。

As a refresher, events are observable occurrences that happen on a network system or device.  
回顧一下，事件是指在網路系統或裝置上發生的可觀察的事件。

This data provides visibility into an environment.  
這些資料提供了對環境的可視性。

Logs are one of the key ways security professionals detect unusual or malicious activity.  
日誌是安全專業人員偵測異常或惡意活動的主要方式之一。

A log is a record of events that occur within an organization's systems.  
日誌是記錄在組織系統內發生的事件的記錄。

System activity is recorded in what's known as a log file or commonly called logs.  
系統活動會記錄在所謂的日誌檔案中，通常稱為日誌。

Almost every device or system can generate logs.  
幾乎每個裝置或系統都可以產生日誌。

Logs contain multiple entries which detail information about a specific event or occurrence.  
日誌包含多條條目，詳細描述有關特定事件或發生的資訊。

Logs are useful to security analysts during incident investigation since they record details of what, where, and when an event occurred on the network.  
日誌在事件調查中對安全分析師非常有用，因為它們記錄了事件發生的時間、地點以及內容。

This includes details like date, time, location, the action made, and the names of the users or systems who performed the action.  
這包括日期、時間、地點、所執行的動作以及執行該動作的使用者或系統名稱等詳細資訊。

These details offer valuable insight, not only for troubleshooting issues related to system performance, but most importantly, for security monitoring.  
這些詳細資訊提供了寶貴的見解，不僅有助於排除系統效能相關的問題，更重要的是有助於安全監控。

Logs allow analysts to build a story and timeline around various event occurrences to understand what exactly happened.  
日誌讓分析師能夠圍繞各種事件發生建立故事和時間線，以了解究竟發生了什麼。

This is done through log analysis.  
這是通過日誌分析來完成的。

Log analysis is the process of examining logs to identify events of interest.  
日誌分析是檢查日誌以識別感興趣事件的過程。

Since there are different sources available to get logs, an enormous volume of log data can be generated.  
由於有多種來源可以獲取日誌，因此可以生成大量的日誌資料。

It's helpful to be selective in what we log, so that we can log efficiently.  
對我們記錄的內容進行選擇性記錄是有幫助的，這樣我們就可以更有效率地記錄。

For example, web applications generate a high volume of log messages, but not all of this data may be relevant to an investigation.  
例如，網頁應用程式會產生大量的日誌訊息，但並非所有資料都與調查相關。

In fact, it may even slow things down.  
事實上，這可能還會讓事情變慢。

Excluding specific data from being logged helps reduce the time spent searching through log data.  
排除特定資料不被記錄有助於減少搜尋日誌資料所花的時間。

You may recall our discussion on SIEM technology.  
你或許還記得我們之前討論過的 SIEM 技術。

SIEM tools provide security professionals with a high-level overview of what happens in a network.  
SIEM 工具為安全專業人員提供網路中發生事件的高層次概覽。

SIEM tools do this by first collecting data from multiple data sources.  
SIEM 工具首先從多個資料來源收集資料來達成這個目的。

Then, the data gets aggregated or centralized in one place.  
接著，資料會被聚合或集中於一個地方。

Finally, the diverse log formats get normalized or converted into a single preferred format.  
最後，各種不同的日誌格式會被標準化或轉換為單一的首選格式。

SIEM tools help process large log volumes from multiple data sources in real-time.  
SIEM 工具幫助實時處理來自多個資料來源的大量日誌資料。

This allows security analysts to quickly search for log data and perform log analysis to support their investigations.  
這使得安全分析師能夠快速搜尋日誌資料並進行日誌分析，以支持他們的調查。

So how do logs get collected?  
那麼，日誌是如何被收集的呢？

Software known as log forwarders collect logs from various sources and automatically forward them to a centralized log repository for storage.  
稱為日誌轉發器的軟體會從各種來源收集日誌，並自動將其轉發至集中式日誌存儲庫進行儲存。

Since different types of devices and systems can create logs, there are different log data sources in an environment.  
由於不同類型的裝置和系統可以創建日誌，因此在環境中存在不同的日誌資料來源。

These include network logs, which are generated by devices such as proxies, routers, switches, and firewalls, and system logs, which are generated by operating systems.  
這些包括網路日誌，由代理伺服器、路由器、交換機和防火牆等裝置生成，還有系統日誌，由作業系統生成。

There's also application logs, which are logs related to software applications, security logs, which are generated by security tools like IDS or IPS, and lastly authentication logs, which record login attempts.  
還有應用程式日誌，這是與軟體應用程式相關的日誌；安全日誌，由像 IDS 或 IPS 這類的安全工具生成；以及身份驗證日誌，記錄登入嘗試。

Here's an example of a network log from a router.  
這裡是一個來自路由器的網路日誌範例。

There are a couple of log entries here, but we'll focus on the first line.  
這裡有幾條日誌條目，但我們將專注於第一行。

Here, we can observe a number of fields.  
在這裡，我們可以觀察到幾個欄位。

First, there's an action specifying ALLOW.  
首先，有一個指定 ALLOW 的動作。

This means that the router's firewall settings allowed access from a specific IP address to google.com.  
這表示路由器的防火牆設置允許來自特定 IP 地址的訪問到 google.com。

Next, there's a field specifying the source, which lists an IP address.  
接下來，有一個指定來源的欄位，列出了一個 IP 地址。

So far, the information from this log entry is telling us that network traffic to google.com from this source IP address is allowed.  
目前，這條日誌條目中的資訊告訴我們，來自這個來源 IP 地址的網路流量被允許訪問 google.com。

The last field specifies the timestamp, which is one of the most essential fields in a log.  
最後一個欄位指定了時間戳，這是日誌中最重要的欄位之一。

We can identify the exact date and time of an action that's occurred.  
我們可以識別發生動作的確切日期和時間。

This is useful for correlating multiple events to develop a timeline of the incident.  
這對於將多個事件進行關聯，並建立事件時間線是有用的。

There you have it! You've analyzed your first network log.  
這就是了！你已經分析了你的第一個網路日誌。

Coming up, we'll continue our discussion on logs and explore log formats.  
接下來，我們將繼續討論日誌並探討日誌格式。

### Best practices for log collection and management

日誌收集與管理的最佳實踐

In this reading, you’ll examine some best practices related to log management, storage, and protection.  
在這篇閱讀中，您將檢視與日誌管理、儲存和保護相關的最佳實踐。

Understanding the best practices related to log collection and management will help improve log searches and better support your efforts in identifying and resolving security incidents.  
了解與日誌收集和管理相關的最佳實踐，將有助於改善日誌搜尋並更有效地支持您識別和解決安全事件的工作。

**Logs**  
**日誌**

Data sources such as devices generate data in the form of events.  
資料來源，如裝置，會以事件的形式產生資料。

A log is a record of events that occur within an organization's systems.  
日誌是記錄在組織系統內發生的事件的記錄。

Logs contain log entries and each entry details information corresponding to a single event that happened on a device or system.  
日誌包含日誌條目，每個條目詳述對應到某個裝置或系統上發生的單一事件的資訊。

Originally, logs served the sole purpose of troubleshooting common technology issues.  
最初，日誌的唯一用途是排除常見的技術問題。

For example, error logs provide information about why an unexpected error occurred and help to identify the root cause of the error so that it can be fixed.  
例如，錯誤日誌提供了為何發生意外錯誤的資訊，並幫助識別錯誤的根本原因，以便進行修復。

Today, virtually all computing devices produce some form of logs that provide valuable insights beyond troubleshooting.  
今天，幾乎所有的計算裝置都會產生某種形式的日誌，提供超越故障排除的寶貴見解。

Security teams access logs from logging receivers like SIEM tools which consolidate logs to provide a central repository for log data.  
安全團隊透過像 SIEM 工具這類的日誌接收器訪問日誌，這些工具會將日誌集中並提供日誌資料的中央儲存庫。

Security professionals use logs to perform log analysis, which is the process of examining logs to identify events of interest.  
安全專業人員使用日誌來進行日誌分析，這是一個檢查日誌以識別感興趣事件的過程。

Logs help uncover the details surrounding the 5 W's of incident investigation: who triggered the incident, what happened, when the incident took place, where the incident took place, and why the incident occurred.  
日誌有助於揭露與事件調查中的五個 W 相關的詳細資訊：誰觸發了事件、發生了什麼、事件發生的時間、事件發生的地點，以及事件為何發生。

**Types of logs**  
**日誌類型**

Depending on the data source, different log types can be produced.  
根據資料來源，可能會產生不同類型的日誌。

Here’s a list of some common log types that organizations should record:  
以下是組織應該記錄的一些常見日誌類型：

-   Network: Network logs are generated by network devices like firewalls, routers, or switches.  
    網路：網路日誌由網路裝置生成，如防火牆、路由器或交換機。
-   System: System logs are generated by operating systems like Chrome OS™, Windows, Linux, or macOS®.  
    系統：系統日誌由作業系統生成，如 Chrome OS™、Windows、Linux 或 macOS®。
-   Application: Application logs are generated by software applications and contain information relating to the events occurring within the application such as a smartphone app.  
    應用程式：應用程式日誌由軟體應用程式生成，並包含與應用程式內發生的事件相關的資訊，例如智慧型手機應用程式。
-   Security: Security logs are generated by various devices or systems such as antivirus software and intrusion detection systems.  
    安全：安全日誌由各種裝置或系統生成，如防毒軟體和入侵偵測系統。  
     Security logs contain security-related information such as file deletion.  
     安全日誌包含與安全相關的資訊，如檔案刪除。
-   Authentication: Authentication logs are generated whenever authentication occurs such as a successful login attempt into a computer.  
    身份驗證：身份驗證日誌在每次身份驗證發生時生成，例如成功的電腦登入嘗試。

**Log details**  
**日誌細節**

Generally, logs contain a date, time, location, action, and author of the action.  
一般來說，日誌包含日期、時間、位置、動作和執行該動作的作者。

Here is an example of an authentication log:  
這裡是一個身份驗證日誌的範例：

`Login Event [05:45:15] User1 Authenticated successfully`  
`登入事件 [05:45:15] User1 成功登入`

Logs contain information and can be adjusted to contain even more information.  
日誌包含資訊，並且可以調整以包含更多資訊。

Verbose logging records additional, detailed information beyond the default log recording.  
詳盡日誌記錄了超出預設日誌記錄的額外詳細資訊。

Here is an example of the same log above but logged as verbose.  
這裡是上述相同日誌，但作為詳盡日誌記錄的範例。

`Login Event [2022/11/16 05:45:15.892673] auth_performer.cc:470 User1 Authenticated successfully from device1 (192.168.1.2)`  
`登入事件 [2022/11/16 05:45:15.892673] auth_performer.cc:470 User1 從裝置1（192.168.1.2）成功登入`

**Log management**  
**日誌管理**

Because all devices produce logs, it can quickly become overwhelming for organizations to keep track of all the logs that are generated.  
由於所有裝置都會產生日誌，組織很快就會覺得難以追蹤所有生成的日誌。

To get the most value from your logs, you need to choose exactly what to log, how to access it easily, and keep it secure using log management.  
為了從日誌中獲得最大的價值，您需要精確選擇要記錄的內容、如何輕鬆存取並使用日誌管理來保持其安全。

Log management is the process of collecting, storing, analyzing, and disposing of log data.  
日誌管理是收集、儲存、分析和處理日誌資料的過程。

**What to log**  
**該記錄什麼**

The most important aspect of log management is choosing what to log.  
日誌管理中最重要的部分是選擇記錄哪些內容。

Organizations are different, and their logging requirements can differ too.  
每個組織不同，且其日誌記錄需求也會有所不同。

It's important to consider which log sources are most likely to contain the most useful information depending on your event of interest.  
根據您的關注事件，考慮哪些日誌來源最有可能包含最有用的資訊是很重要的。

This might be configuring log sources to reduce the amount of data they record, such as excluding excessive verbosity.  
這可能涉及配置日誌來源以減少其記錄的資料量，例如排除過多的冗長資訊。

Some information, including but not limited to phone numbers, email addresses, and names, form personally identifiable information (PII), which requires special handling and in some jurisdictions might not be possible to be logged.  
某些資訊，包括但不限於電話號碼、電子郵件地址和姓名，構成個人識別資訊（PII），這需要特殊處理，在某些司法管轄區可能無法記錄。

**The issue with overlogging**  
**過度記錄的問題**

From a security perspective, it can be tempting to log everything.  
從安全的角度來看，記錄一切似乎很有吸引力。

This is the most common mistake organizations make.  
這是組織最常犯的錯誤。

Just because it can be logged, doesn't mean it needs to be logged.  
只因為可以記錄，並不代表需要記錄。

Storing excessive amounts of logs can have many disadvantages with some SIEM tools.  
儲存過多的日誌可能會對某些 SIEM 工具帶來許多不利影響。

For example, overlogging can increase storage and maintenance costs.  
例如，過度記錄會增加儲存和維護成本。

Additionally, overlogging can increase the load on systems, which can cause performance issues and affect usability, making it difficult to search for and identify important events.  
此外，過度記錄會增加系統的負擔，可能導致效能問題並影響可用性，使得搜尋和識別重要事件變得困難。

**Log retention**  
**日誌保留**

Organizations might operate in industries with regulatory requirements.  
組織可能會在有法規要求的行業中運營。

For example, some regulations require organizations to retain logs for set periods of time and organizations can implement log retention practices in their log management policy.  
例如，一些法規要求組織保留日誌一段固定的時間，組織可以在其日誌管理政策中實施日誌保留實踐。

Organizations that operate in the following industries might need to modify their log management policy to meet regulatory requirements:  
在以下行業運營的組織可能需要修改其日誌管理政策，以符合法規要求：

-   Public sector industries, like the Federal Information Security Modernization Act (FISMA)  
    公共部門行業，如聯邦資訊安全現代化法案（FISMA）
-   Healthcare industries, like the Health Insurance Portability and Accountability Act of 1996 (HIPAA)  
    醫療保健行業，如 1996 年健康保險流通與責任法案（HIPAA）
-   Financial services industries, such as the Payment Card Industry Data Security Standard (PCI DSS), the Gramm-Leach-Bliley Act (GLBA), and the Sarbanes-Oxley Act of 2002 (SOX)  
    金融服務行業，如支付卡行業資料安全標準（PCI DSS）、格雷厄姆-李奇-布萊利法案（GLBA）和 2002 年薩班斯-奧克斯利法案（SOX）

**Log protection**  
**日誌保護**

Along with management and retention, the protection of logs is vital in maintaining log integrity.  
除了管理和保留，保護日誌對於維護日誌的完整性至關重要。

It’s not unusual for malicious actors to modify logs in attempts to mislead security teams and to even hide their activity.  
惡意行為者修改日誌以誤導安全團隊甚至隱藏他們的活動並不罕見。

Storing logs in a centralized log server is a way to maintain log integrity.  
將日誌儲存在集中式日誌伺服器中是維護日誌完整性的一種方式。

When logs are generated, they get sent to a dedicated server instead of getting stored on a local machine.  
當日誌生成時，它們會被發送到專用伺服器，而不是儲存在本地機器上。

This makes it more difficult for attackers to access logs because there is a barrier between the attacker and the log location.  
這使得攻擊者更難訪問日誌，因為攻擊者與日誌位置之間有一道障礙。

**Key takeaways**  
**主要要點**

It's important to understand how to properly collect, store, and protect logs because they are integral to incident investigations.  
了解如何正確收集、儲存和保護日誌是很重要的，因為它們對事件調查至關重要。

Having a detailed plan for log management helps improve the usefulness of logs and resource efficiency.  
擁有詳細的日誌管理計劃有助於提高日誌的有用性和資源效率。

**JavaScript Object Notation (JSON)**  
**JavaScript 物件表示法（JSON）**

JavaScript Object Notation (JSON) is a file format that is used to store and transmit data.  
JavaScript 物件表示法（JSON）是一種用來儲存和傳輸資料的檔案格式。

JSON is known for being lightweight and easy to read and write.  
JSON 以其輕量級和易於閱讀及書寫著稱。

It is used for transmitting data in web technologies and is also commonly used in cloud environments.  
它用於網頁技術中的資料傳輸，並且在雲端環境中也很常見。

JSON syntax is derived from JavaScript syntax.  
JSON 語法來源於 JavaScript 語法。

If you are familiar with JavaScript, you might recognize that JSON contains components from JavaScript including:  
如果你熟悉 JavaScript，你可能會認出 JSON 包含了來自 JavaScript 的組件，包括：

-   Key-value pairs
-   Commas
-   Double quotes
-   Curly brackets
-   Square brackets

**Key-value pairs**  
**鍵值對**

A key-value pair is a set of data that represents two linked items: a key and its corresponding value.  
鍵值對是一組資料，表示兩個相互關聯的項目：一個鍵及其對應的值。

A key-value pair consists of a key followed by a colon, and then followed by a value.  
鍵值對由一個鍵後接冒號，再後接一個值組成。

An example of a key-value pair is "Alert": "Malware".  
鍵值對的範例是"Alert": "Malware"。

Note: For readability, it is recommended that key-value pairs contain a space before or after the colon that separates the key and value.  
注意：為了可讀性，建議在冒號前後留有空格，以分隔鍵和值。

**Commas**  
**逗號**

Commas are used to separate data.  
逗號用來分隔資料。

For example: `"Alert": "Malware", "Alert code": 1090, "severity": 10`.  
例如：`"Alert": "Malware", "Alert code": 1090, "severity": 10`。

**Double quotes**  
**雙引號**

Double quotes are used to enclose text data, which is also known as a string, for example: `"Alert": "Malware"`.  
雙引號用來括住文字資料，也就是所謂的字串，例如：`"Alert": "Malware"`。

Data that contains numbers is not enclosed in quotes, like this: `"Alert code": 1090`.  
包含數字的資料則不會用引號括住，像這樣：`"Alert code": 1090`。

**Curly brackets**  
**大括號**

Curly brackets enclose an object, which is a data type that stores data in a comma-separated list of key-value pairs.  
大括號括住一個物件，這是一種將資料儲存在以逗號分隔的鍵值對列表中的資料類型。

Objects are often used to describe multiple properties for a given key.  
物件通常用來描述給定鍵的多個屬性。

JSON log entries start and end with a curly bracket.  
JSON 日誌條目以大括號開始和結束。

In this example, User is the object that contains multiple properties:  
在這個範例中，User 是包含多個屬性的物件：

`"User":`

```json
{
    "id": "1234",
    "name": "user",
    "role": "engineer"
}
```

**Square brackets**  
**方括號**

Square brackets are used to enclose an array, which is a data type that stores data in a comma-separated ordered list.  
方括號用來括住陣列，這是一種將資料儲存在以逗號分隔的有序列表中的資料類型。

Arrays are useful when you want to store data as an ordered collection, for example: ["Administrators", "Users", "Engineering"].  
當你想要將資料儲存為有序集合時，陣列非常有用，例如：`["Administrators", "Users", "Engineering"]`。

**Syslog**  
**Syslog**

Syslog is a standard for logging and transmitting data.  
Syslog 是一個用於記錄和傳輸資料的標準。

It can be used to refer to any of its three different capabilities:  
它可以用來指稱其三種不同的功能：

-   Protocol: The syslog protocol is used to transport logs to a centralized log server for log management.  
    協議：syslog 協議用來將日誌傳輸到集中式日誌伺服器進行日誌管理。

    It uses port 514 for plaintext logs and port 6514 for encrypted logs.  
    它使用端口 514 傳輸明文日誌，使用端口 6514 傳輸加密日誌。

-   Service: The syslog service acts as a log forwarding service that consolidates logs from multiple sources into a single location.  
    服務：syslog 服務作為一個日誌轉發服務，將來自多個來源的日誌整合到一個地方。

    The service works by receiving and then forwarding any syslog log entries to a remote server.  
    該服務通過接收並將任何 syslog 日誌條目轉發到遠端伺服器來運作。

-   Log format: The syslog log format is one of the most commonly used log formats that you will be focusing on.  
    日誌格式：syslog 日誌格式是你將會專注的最常用日誌格式之一。

    It is the native logging format used in Unix® systems.  
    它是 Unix® 系統中使用的原生日誌格式。

    It consists of three components: a header, structured-data, and a message.  
    它由三個組成部分：標頭、結構化數據和訊息。

**Syslog 日誌範例**

Here is an example of a syslog entry that contains all three components: a header, followed by structured-data, and a message:  
這裡是一個包含所有三個組成部分的 syslog 日誌範例：標頭，接著是結構化數據，最後是訊息：

`<236>1 2022-03-21T01:11:11.003Z virtual.machine.com evntslog - ID01 [user@32473 iut="1" eventSource="Application" eventID="9999"]

**標頭**

標頭包含像是時間戳、主機名稱（發送日誌的機器名稱）、應用程式名稱以及訊息 ID 等詳細資訊。

-   Timestamp: The timestamp in this example is 2022-03-21T01:11:11.003Z, where 2022-03-21 is the date in YYYY-MM-DD format.  
    時間戳：此範例中的時間戳是 2022-03-21T01:11:11.003Z，其中 2022-03-21 是 YYYY-MM-DD 格式的日期。

    T 用來分隔日期和時間。

    01:11:11.003 是 24 小時制的時間格式，並包括毫秒數 003。

日誌條目的結構化數據部分包含額外的日誌資訊。

這些資訊被括在方括號中，並以鍵值對形式結構化。

**XML (eXtensible Markup Language)**  
**XML（可擴展標記語言）**

XML (eXtensible Markup Language) is a language and a format used for storing and transmitting data.  
XML（可擴展標記語言）是一種用於儲存和傳輸資料的語言和格式。

XML is a native file format used in Windows systems.  
XML 是 Windows 系統中使用的原生檔案格式。

XML syntax uses the following:  
XML 語法使用以下元素：

-   Tags
-   Elements
-   Attributes

**Tags**  
**標籤**

XML uses tags to store and identify data.  
XML 使用標籤來儲存和識別資料。

Tags are pairs that must contain a start tag and an end tag.  
標籤是成對的，必須包含開始標籤和結束標籤。

The start tag encloses data with angle brackets, for example `<tag>`, whereas the end of a tag encloses data with angle brackets and a forward slash like this: `</tag>`.  
開始標籤用尖括號括住資料，例如`<tag>`，而結束標籤則用尖括號和正斜線括住資料，如這樣：`</tag>`。

**Elements**  
**元素**

XML elements include both the data contained inside of a tag and the tags itself.  
XML 元素包括標籤內部包含的資料以及標籤本身。

All XML entries must contain at least one root element.  
所有 XML 條目必須至少包含一個根元素。

Root elements contain other elements that sit underneath them, known as child elements.  
根元素包含其他位於其下方的元素，稱為子元素。

Here is an example:  
這裡是一個範例：

```xml
<Event>
    <EventID>4688</EventID>
    <Version>5</Version>
</Event>
```

In this example, `<Event>` is the root element and contains two child elements `<EventID>` and `<Version>`.  
在這個範例中，`<Event>`是根元素，並包含兩個子元素`<EventID>`和`<Version>`。  
There is data contained in each respective child element.  
每個子元素中包含資料。

**Attributes**  
**屬性**

XML elements can also contain attributes.  
XML 元素也可以包含屬性。

Attributes are used to provide additional information about elements.  
屬性用來提供有關元素的額外資訊。

Attributes are included as the second part of the tag itself and must always be quoted using either single or double quotes.  
屬性包含在標籤本身的第二部分，並且必須始終使用單引號或雙引號來括起來。

For example:  
例如：

```
<EventData>
    <Data Name='SubjectUserSid'>S-2-3-11-160321</Data>
    <Data Name='SubjectUserName'>JSMITH</Data>
    <Data Name='SubjectDomainName'>ADCOMP</Data>
    <Data Name='SubjectLogonId'>0x1cf1c12</Data>
    <Data Name='NewProcessId'>0x1404</Data>
</EventData>
```

In the first line for this example, the tag is `<Data>` and it uses the attribute `Name='SubjectUserSid'` to describe the data enclosed in the tag `S-2-3-11-160321`.  
在這個範例的第一行中，標籤是`<Data>`，它使用屬性`Name='SubjectUserSid'`來描述標籤中所包含的資料`S-2-3-11-160321`。

**CSV (Comma Separated Value)**  
**CSV（逗號分隔值）**

CSV (Comma Separated Value) uses commas to separate data values.  
CSV（逗號分隔值）使用逗號來分隔資料值。

In CSV logs, the position of the data corresponds to its field name, but the field names themselves might not be included in the log.  
在 CSV 日誌中，資料的位置對應到其欄位名稱，但欄位名稱本身可能不會包含在日誌中。

It’s critical to understand what fields the source device (like an IPS, firewall, scanner, etc.) is including in the log.  
了解來源裝置（如 IPS、防火牆、掃描器等）在日誌中包含哪些欄位是非常重要的。

Here is an example:  
這裡是一個範例：

`2009-11-24T21:27:09.534255,ALERT,192.168.2.7, 1041,x.x.250.50,80,TCP,ALLOWED,1:2001999:9,"ET MALWARE BTGrab.com Spyware Downloading Ads",1`

**CEF (Common Event Format)**  
**CEF（通用事件格式）**

Common Event Format (CEF) is a log format that uses key-value pairs to structure data and identify fields and their corresponding values.  
通用事件格式（CEF）是一種使用鍵值對來結構化資料並識別欄位及其對應值的日誌格式。

The CEF syntax is defined as containing the following fields:  
CEF 語法被定義為包含以下欄位：

`CEF:Version|Device Vendor|Device Product|Device Version|Signature ID|Name|Severity|Extension`  
`CEF:版本|裝置廠商|裝置產品|裝置版本|簽名ID|名稱|嚴重性|擴展`

Fields are all separated with a pipe character |.  
所有欄位都以管道符號`|`分隔。

However, anything in the Extension part of the CEF log entry must be written in a key-value format.  
然而，CEF 日誌條目中擴展部分的任何內容必須以鍵值對格式書寫。

Syslog is a common method used to transport logs like CEF.  
Syslog 是用來傳輸像 CEF 這樣的日誌的常見方法。

When Syslog is used a timestamp and hostname will be prepended to the CEF message.  
當使用 Syslog 時，時間戳和主機名稱會被加在 CEF 訊息前面。

Here is an example of a CEF log entry that details malicious activity relating to a worm infection:  
這裡是一個 CEF 日誌條目的範例，詳述與蠕蟲感染相關的惡意活動：

`Sep 29 08:26:10 host CEF:1|Security|threatmanager|1.0|100|worm successfully stopped|10|src=10.0.0.2 dst=2.1.2.2 spt=1232`

Here is a breakdown of the fields:  
以下是欄位的解析：

-   Syslog Timestamp: Sep 29 08:26:10  
    Syslog 時間戳：Sep 29 08:26:10

-   Syslog Hostname: host  
    Syslog 主機名稱：host

-   Version: CEF:1  
    版本：CEF:1

-   Device Vendor: Security  
    裝置廠商：Security

-   Device Product: threatmanager  
    裝置產品：threatmanager

-   Device Version: 1.0  
    裝置版本：1.0

-   Signature ID: 100  
    簽名 ID：100

-   Name: worm successfully stopped  
    名稱：蠕蟲成功停止

-   Severity: 10  
    嚴重性：10

-   Extension: This field contains data written as key-value pairs.  
    擴展：此欄位包含以鍵值對形式書寫的資料。

    There are two IP addresses, `src=10.0.0.2` and `dst=2.1.2.2`, and a source port number spt=1232.  
    有兩個 IP 地址，`src=10.0.0.2`和`dst=2.1.2.2`，以及一個源端口號 spt=1232。

    Extensions are not required and are optional to add.  
    擴展不是必須的，可以選擇性地添加。

This log entry contains details about a Security application called threatmanager that successfully stopped a worm from spreading from the internal network at 10.0.0.2 to the external network 2.1.2.2 through the port 1232.  
這條日誌條目包含了名為 threatmanager 的安全應用程式的詳細資訊，該應用程式成功阻止了蠕蟲從內部網路 10.0.0.2 傳播到外部網路 2.1.2.2，並通過端口 1232 進行傳播。

A high severity level of 10 is reported.  
報告了嚴重性級別為 10 的事件。

Note: Extensions and syslog prefix are optional to add to a CEF log.  
注意：擴展和 syslog 前綴是可選的，可以添加到 CEF 日誌中。

**Key takeaways**  
**主要要點**

There is no standard format used in logging, and many different log formats exist.  
日誌記錄中並沒有統一的標準格式，並且存在許多不同的日誌格式。

As a security analyst, you will analyze logs that originate from different sources.  
作為安全分析師，你將分析來自不同來源的日誌。

Knowing how to interpret different log formats will help you determine key information that you can use to support your investigations.  
了解如何解釋不同的日誌格式將幫助你確定關鍵資訊，以支持你的調查。

## Overview of intrusion detection systems (IDS) 入侵偵測系統（IDS）概述

### Security monitoring with detection tools 使用偵測工具進行安全監控

Detection requires data, and this data can come from various data sources.  
偵測需要資料，這些資料可以來自各種資料來源。

You've already explored how different devices produce logs.  
你已經了解了不同裝置如何產生日誌。

Now we'll examine how different detection technologies monitor devices and log different types of system activity, like network and endpoint telemetry.  
現在我們將探討不同的偵測技術如何監控裝置並記錄不同類型的系統活動，如網路和端點遙測。

Telemetry is the collection and transmission of data for analysis.  
遙測是為了分析而收集和傳輸資料的過程。

While logs record events occurring on systems, telemetry describes the data itself.  
日誌記錄系統上發生的事件，而遙測描述的是資料本身。

For example, packet captures are considered network telemetry.  
例如，封包擷取被視為網路遙測。

For security professionals, logs and telemetry are sources of evidence that can be used to answer questions during investigations.  
對於安全專業人員來說，日誌和遙測是可以用來回答調查問題的證據來源。

Previously, you learned about an intrusion detection system, or IDS.  
之前，你學過入侵偵測系統（IDS）。

Remember that IDS is an application that monitors activity and alerts on possible intrusions.  
記住，IDS 是一種監控活動並對可能的入侵發出警報的應用程式。

This includes monitoring different parts of a system or network like an endpoint.  
這包括監控系統或網路的不同部分，如端點。

An endpoint is any device connected on a network, such as a laptop, tablet, desktop computer, or a smartphone.  
端點是任何連接在網路上的裝置，如筆記型電腦、平板電腦、桌面電腦或智慧型手機。

Endpoints are entry points into a network, which makes them key targets for malicious actors looking to gain unauthorized access into a system.  
端點是進入網路的入口，這使得它們成為尋求未經授權訪問系統的惡意攻擊者的主要目標。

To monitor endpoints for threats or attacks, a host-based intrusion detection system can be used.  
為了監控端點的威脅或攻擊，可以使用主機型入侵偵測系統。

It's an application that monitors the activity of the host on which it's installed.  
這是一個監控安裝它的主機活動的應用程式。

To clarify, a host is any device that communicates with other devices on a network, similar to an endpoint.  
為了澄清，主機是任何在網路上與其他裝置通訊的裝置，類似於端點。

Host-based intrusion detection systems are installed as an agent on a single host, such as a laptop computer or a server.  
主機型入侵偵測系統作為代理程式安裝在單一主機上，如筆記型電腦或伺服器。

Depending on its configuration, host-based intrusion detection systems will monitor the host on which it's installed to detect suspicious activity.  
根據其配置，主機型入侵偵測系統將監控安裝它的主機，來偵測可疑活動。

Once something has been detected, it records output as logs and an alert gets generated.  
一旦偵測到某些活動，它會將輸出記錄為日誌並產生警報。

What if we wanted to monitor a network? A network-based intrusion detection system collects and analyzes network traffic and network data.  
如果我們想要監控網路怎麼辦？網路型入侵偵測系統會收集並分析網路流量和網路資料。

Network-based intrusion detection systems work similar to packet sniffers because they analyze network traffic and network data on a specific point in the network.  
網路型入侵偵測系統的運作方式與封包嗅探器相似，因為它們分析網路中某個特定點的網路流量和網路資料。

It's common to deploy multiple IDS sensors at different points in the network to achieve adequate visibility.  
在網路的不同點部署多個 IDS 感測器來獲得足夠的可見性是很常見的。

When suspicious or unusual network activity is detected, the network-based intrusion detection system logs it and generates an alert.  
當偵測到可疑或異常的網路活動時，網路型入侵偵測系統會記錄並產生警報。

In this example, the network-based intrusion detection system is monitoring the traffic that's both coming from and going to the internet.  
在這個範例中，網路型入侵偵測系統正在監控進出網際網路的流量。

Intrusion detection systems use different types of detection methods.  
入侵偵測系統使用不同類型的偵測方法。

One of the most common methods is signature analysis.  
最常見的方法之一是簽名分析。

Signature analysis is a detection method used to find events of interest.  
簽名分析是一種用來尋找感興趣事件的偵測方法。

A signature specifies a set of rules that an IDS refers to when it monitors activity.  
簽名指定了一組規則，IDS 在監控活動時會參照這些規則。

If the activity matches the rules in the signature, the IDS logs it and sends out an alert.  
如果活動與簽名中的規則匹配，IDS 會記錄並發送警報。

For example, a signature can be written to generate an alert if a failed login on a system happens three times in a row, which suggests a possible password attack.  
例如，簽名可以寫成當系統登入失敗三次時產生警報，這表示可能發生了密碼攻擊。

Before alerts are generated, the activity must be logged.  
在產生警報之前，活動必須先被記錄。

IDS technologies record the information of the devices, systems, and networks which they monitor as IDS logs.  
IDS 技術會記錄它們監控的裝置、系統和網路的資訊，作為 IDS 日誌。

IDS logs can then be sent, stored, and analyzed in a centralized log repository like a SIEM.  
然後，IDS 日誌可以被發送、儲存並在像 SIEM 這樣的集中式日誌儲存庫中分析。

接下來，我們將探索如何閱讀和配置簽名。

Meet you there!  
到時見！

### Detection tools and techniques 偵測工具與技術

In this reading, you’ll examine the different types of intrusion detection system (IDS) technologies and the alerts they produce.  
在這篇閱讀中，你將檢視不同類型的入侵偵測系統（IDS）技術以及它們產生的警報。

You’ll also explore the two common detection techniques used by detection systems.  
你還將探索偵測系統使用的兩種常見偵測技術。

Understanding the capabilities and limitations of IDS technologies and their detection techniques will help you interpret security information to identify, analyze, and respond to security events.  
了解 IDS 技術及其偵測技術的能力與限制，將幫助你解讀安全資訊，進而識別、分析並回應安全事件。

As you’ve learned, an intrusion detection system (IDS) is an application that monitors system activity and alerts on possible intrusions.  
如你所學，入侵偵測系統（IDS）是一個監控系統活動並對可能的入侵發出警報的應用程式。

IDS technologies help organizations monitor the activity that happens on their systems and networks to identify indications of malicious activity.  
IDS 技術幫助組織監控其系統和網路上發生的活動，以識別惡意活動的徵兆。

Depending on the location you choose to set up an IDS, it can be either host-based or network-based.  
根據你選擇設置 IDS 的位置，它可以是主機型或網路型。

**Host-based intrusion detection system**  
**主機型入侵偵測系統**

A host-based intrusion detection system (HIDS) is an application that monitors the activity of the host on which it's installed.  
主機型入侵偵測系統（HIDS）是一個監控其安裝所在主機活動的應用程式。

A HIDS is installed as an agent on a host.  
HIDS 作為代理程式安裝在主機上。

A host is also known as an endpoint, which is any device connected to a network like a computer or a server.  
主機也稱為端點，是任何連接到網路的裝置，例如電腦或伺服器。

Typically, HIDS agents are installed on all endpoints and used to monitor and detect security threats.  
通常，HIDS 代理程式會安裝在所有端點上，用來監控並偵測安全威脅。

A HIDS monitors internal activity happening on the host to identify any unauthorized or abnormal behavior.  
HIDS 監控主機上發生的內部活動，以識別任何未經授權或異常的行為。

If anything unusual is detected, such as the installation of an unauthorized application, the HIDS logs it and sends out an alert.  
如果偵測到任何異常情況，例如安裝未經授權的應用程式，HIDS 會記錄並發出警報。

In addition to monitoring inbound and outbound traffic flows, HIDS can have additional capabilities, such as monitoring file systems, system resource usage, user activity, and more.  
除了監控進出流量外，HIDS 還可以具備其他功能，例如監控檔案系統、系統資源使用、使用者活動等。

This diagram shows a HIDS tool installed on a computer.  
此圖顯示一個安裝在電腦上的 HIDS 工具。

The dotted circle around the host indicates that it is only monitoring the local activity on the single computer on which it’s installed.  
圍繞主機的虛線圓圈表示它僅監控安裝在單一電腦上的本地活動。

A network diagram with a host-based intrusion detection system monitoring a single computer.  
一個網路圖，顯示主機型入侵偵測系統監控單一電腦。

**Network-based intrusion detection system**  
**網路型入侵偵測系統**

A network-based intrusion detection system (NIDS) is an application that collects and monitors network traffic and network data.  
網路型入侵偵測系統（NIDS）是一個收集並監控網路流量和網路資料的應用程式。

NIDS software is installed on devices located at specific parts of the network that you want to monitor.  
NIDS 軟體安裝在網路中你希望監控的特定位置的裝置上。

The NIDS application inspects network traffic from different devices on the network.  
NIDS 應用程式檢查來自網路中不同裝置的網路流量。

If any malicious network traffic is detected, the NIDS logs it and generates an alert.  
如果偵測到任何惡意的網路流量，NIDS 會記錄並產生警報。

This diagram shows a NIDS that is installed on a network.  
此圖顯示一個安裝在網路上的 NIDS。

The highlighted circle around the server and computers indicates that the NIDS is installed on the server and is monitoring the activity of the computers.  
圍繞伺服器和電腦的高亮圓圈表示 NIDS 安裝在伺服器上，並監控電腦的活動。

Network-based intrusion detection system installed on a server monitoring network communications between multiple computers.  
安裝在伺服器上的網路型入侵偵測系統，監控多台電腦之間的網路通信。

Using a combination of HIDS and NIDS to monitor an environment can provide a multi-layered approach to intrusion detection and response.  
結合使用 HIDS 和 NIDS 來監控一個環境，可以提供多層次的入侵偵測與回應方法。

HIDS and NIDS tools provide a different perspective on the activity occurring on a network and the individual hosts that are connected to it.  
HIDS 和 NIDS 工具提供了對網路及其連接的個別主機上發生活動的不同觀點。

This helps provide a comprehensive view of the activity happening in an environment.  
這有助於提供對環境中發生的活動的全面了解。

**Detection techniques**  
**偵測技術**

Detection systems can use different techniques to detect threats and attacks.  
偵測系統可以使用不同的技術來偵測威脅和攻擊。

The two types of detection techniques that are commonly used by IDS technologies are signature-based analysis and anomaly-based analysis.  
IDS 技術常用的兩種偵測技術是基於簽名的分析和基於異常的分析。

**Signature-based analysis**  
**基於簽名的分析**

Signature analysis, or signature-based analysis, is a detection method that is used to find events of interest.  
簽名分析，或稱為基於簽名的分析，是一種用來尋找感興趣事件的偵測方法。

A signature is a pattern that is associated with malicious activity.  
簽名是一種與惡意活動相關的模式。

Signatures can contain specific patterns like a sequence of binary numbers, bytes, or even specific data like an IP address.  
簽名可以包含特定的模式，例如一連串的二進位數字、位元組，甚至是像 IP 地址這樣的特定資料。

Previously, you explored the Pyramid of Pain, which is a concept that prioritizes the different types of indicators of compromise (IoCs) associated with an attack or threat, such as IP addresses, tools, tactics, techniques, and more.  
之前，你探討了痛苦金字塔（Pyramid of Pain），這是一個概念，用來優先排序與攻擊或威脅相關的不同類型的妥協指標（IoC），例如 IP 地址、工具、戰術、技術等。

IoCs and other indicators of attack can be useful for creating targeted signatures to detect and block attacks.  
IoC 和其他攻擊指標對於創建針對性的簽名，以偵測和封鎖攻擊是有用的。

Different types of signatures can be used depending on which type of threat or attack you want to detect.  
可以根據你想要偵測的威脅或攻擊類型使用不同類型的簽名。

For example, an anti-malware signature contains patterns associated with malware.  
例如，反惡意軟體簽名包含與惡意軟體相關的模式。

This can include malicious scripts that are used by the malware.  
這可以包括惡意軟體所使用的惡意腳本。

IDS tools will monitor an environment for events that match the patterns defined in this malware signature.  
IDS 工具會監控環境中與這些惡意軟體簽名中定義的模式相符的事件。

If an event matches the signature, the event gets logged and an alert is generated.  
如果事件與簽名匹配，該事件會被記錄並產生警報。

**Advantages**  
**優勢**

-   Low rate of false positives: Signature-based analysis is very efficient at detecting known threats because it is simply comparing activity to signatures.  
    假陽性率低：基於簽名的分析對於偵測已知威脅非常有效，因為它只是將活動與簽名進行比較。

    This leads to fewer false positives.  
    這樣可以減少假陽性的情況。

    Remember that a false positive is an alert that incorrectly detects the presence of a threat.  
    記住，假陽性是指錯誤偵測到威脅存在的警報。

**Disadvantages**  
**劣勢**

-   Signatures can be evaded: Signatures are unique, and attackers can modify their attack behaviors to bypass the signatures.  
    簽名可能被迴避：簽名是唯一的，攻擊者可以修改他們的攻擊行為以繞過簽名。

    For example, attackers can make slight modifications to malware code to alter its signature and avoid detection.  
    例如，攻擊者可以對惡意軟體的程式碼進行輕微修改，以改變其簽名並避開偵測。

-   Signatures require updates: Signature-based analysis relies on a database of signatures to detect threats.  
    簽名需要更新：基於簽名的分析依賴簽名資料庫來偵測威脅。

    Each time a new exploit or attack is discovered, new signatures must be created and added to the signature database.  
    每當發現新的漏洞或攻擊時，必須創建新的簽名並將其添加到簽名資料庫中。

-   Inability to detect unknown threats: Signature-based analysis relies on detecting known threats through signatures.  
    無法偵測未知威脅：基於簽名的分析依賴通過簽名來偵測已知的威脅。

    Unknown threats can't be detected, such as new malware families or zero-day attacks, which are exploits that were previously unknown.  
    例如新的惡意軟體家族或零日攻擊（這些是之前未知的漏洞攻擊），是無法被偵測到的。

**Anomaly-based analysis**  
**基於異常的分析**

Anomaly-based analysis is a detection method that identifies abnormal behavior.  
基於異常的分析是一種識別異常行為的偵測方法。

There are two phases to anomaly-based analysis: a training phase and a detection phase.  
基於異常的分析有兩個階段：訓練階段和偵測階段。

In the training phase, a baseline of normal or expected behavior must be established.  
在訓練階段，必須建立正常或預期行為的基準。

Baselines are developed by collecting data that corresponds to normal system behavior.  
基準是通過收集與正常系統行為對應的資料來建立的。

In the detection phase, the current system activity is compared against this baseline.  
在偵測階段，當前的系統活動將與此基準進行比較。

Activity that happens outside of the baseline gets logged, and an alert is generated.  
任何超出基準的活動將被記錄並產生警報。

**Advantages**  
**優勢**

Ability to detect new and evolving threats: Unlike signature-based analysis, which uses known patterns to detect threats, anomaly-based analysis can detect unknown threats.  
能夠偵測新的和不斷演變的威脅：與基於簽名的分析（使用已知模式來偵測威脅）不同，基於異常的分析能夠偵測未知威脅。

**Disadvantages**  
**劣勢**

-   High rate of false positives: Any behavior that deviates from the baseline can be flagged as abnormal, including non-malicious behaviors.  
    假陽性率高：任何偏離基準的行為都可能被標記為異常，包括非惡意行為。

    This leads to a high rate of false positives.  
    這導致假陽性率很高。

-   Pre-existing compromise: The existence of an attacker during the training phase will include malicious behavior in the baseline.  
    事前妥協：如果在訓練階段存在攻擊者，惡意行為將被包含在基準中。

    This can lead to missing a pre-existing attacker.  
    這可能會導致錯過一個已經存在的攻擊者。

**Key takeaways**  
**主要要點**

IDS technologies are an essential security tool that you will encounter in your security journey.

### Components of a detection signature

### 偵測簽名的組成

As a security analyst, you may be tasked with writing, customizing, or testing signatures.  
作為安全分析師，你可能會被指派編寫、客製化或測試簽名。

To do this, you'll use IDS tools.  
為了完成這項任務，你將使用 IDS 工具。

So in this section, we'll examine signature syntax and by the end, you'll be able to read a signature.  
在本節中，我們將檢視簽名語法，並在結束時讓你能夠閱讀簽名。

A signature specifies detection rules.  
簽名指定偵測規則。

These rules outline the types of network intrusions you want an IDS to detect.  
這些規則概述了你希望 IDS 偵測的網路入侵類型。

For example, a signature can be written to detect and alert on suspicious traffic attempting to connect to a port.  
例如，可以編寫簽名來偵測並對試圖連接到端口的可疑流量發出警報。

Rule language differs depending on different network intrusion detection systems.  
規則語言根據不同的網路入侵偵測系統而有所不同。

The term network intrusion detection system is often abbreviated as the acronym N-I-D-S and pronounced NIDS.  
「網路入侵偵測系統」這個術語通常縮寫為 N-I-D-S，並發音為 NIDS。

Generally, NIDS rules consists of three components: an action, a header, and rule options.  
通常，NIDS 規則包含三個組成部分：動作、標頭和規則選項。

Now, let's examine each of these three components in more detail.  
現在，讓我們更詳細地檢視這三個組成部分。

Typically, the action is the first item specified in a signature.  
通常，動作是簽名中指定的第一項內容。

This determines the action to take if the rule criteria matches are met.  
這決定了當規則條件匹配時應採取的動作。

Actions differ across NIDS rule languages, but some common actions are: alert, pass, or reject.  
不同的 NIDS 規則語言有不同的動作，但一些常見的動作有：警報、通過或拒絕。

Using our example, if a rule specifies to alert on suspicious network traffic that establishes an unusual connection to a port, the IDS will inspect the traffic packets and send out an alert.  
以我們的範例來說，如果規則指定對建立到端口的異常連接的可疑網路流量發出警報，IDS 將檢查流量封包並發出警報。

The header defines the signature's network traffic.  
標頭定義了簽名的網路流量。

These include information such as source and destination IP addresses, source and destination ports, protocols, and traffic direction.  
這些資訊包括來源和目的 IP 地址、來源和目的端口、協議以及流量方向等。

If we want to detect an alert on suspicious traffic connecting to a port, we have to first define the source of the suspicious traffic in the header.  
如果我們想要偵測對連接到端口的可疑流量發出警報，我們必須首先在標頭中定義可疑流量的來源。

Suspicious traffic can originate from IP addresses outside the local network.  
可疑流量可以來自本地網路外的 IP 地址。

It can also use specific or unusual protocols.  
它也可以使用特定或不尋常的協議。

We can specify external IP addresses and these protocols in the header.  
我們可以在標頭中指定外部 IP 地址和這些協議。

Here's an example of how header information may appear in a basic rule.  
這裡是標頭資訊如何在基本規則中顯示的範例。

First, we can observe that the protocol, TCP, is the first listed item in the signature.  
首先，我們可以觀察到協議 TCP 是簽名中列出的第一項。

Next, the source IP address 10.120.170.17 and the source port number is specified as being any.  
接著，來源 IP 地址 10.120.170.17 和來源端口號被指定為任意。

The arrow in the middle of the signature indicates the direction of the network traffic.  
簽名中間的箭頭表示網路流量的方向。

So we know it's originating from the source IP 10.120.170.17 from any port going to the following destination IP address 133.113.202.181 and destination port 80.  
所以我們知道它來自來源 IP 10.120.170.17 的任意端口，並前往目的 IP 地址 133.113.202.181 和目的端口 80。

The rule options lets you customize signatures with additional parameters.  
規則選項讓你使用額外的參數來自訂簽名。

There are many different options available to use.  
有許多不同的選項可供使用。

For instance, you can set options to match the content of a network packet to detect malicious payloads.  
例如，你可以設置選項來匹配網路封包的內容，以偵測惡意負載。

Malicious payloads reside in a packet's data and perform malicious activity like deleting or encrypting data.  
惡意負載存在於封包的資料中，並執行像是刪除或加密資料等惡意活動。

Configuring rule options helps in narrowing down network traffic, so you can find exactly what you're looking for.  
配置規則選項有助於縮小網路流量範圍，讓你能精確找到所需的資訊。

Typically, rule options are separated by semi-colons and enclosed in parentheses.  
通常，規則選項由分號分隔並括在圓括號內。

In this example, we can examine that the rule options are enclosed in a pair of parentheses and are also separated with semi-colons.  
在這個範例中，我們可以看到規則選項被括在一對圓括號中，並且也用分號分隔。

The first rule option, msg, which stands for message, provides the alert's text.  
第一個規則選項 msg，代表訊息，提供警報的文字。

In this case, the alert will print out the text: "This is a message." There's also the option sid, which stands for signature ID.  
在這個例子中，警報會顯示出文字："This is a message." 還有選項 sid，代表簽名 ID。

This attaches a unique id to each signature.  
這會將一個唯一的 ID 附加到每個簽名上。

The rev option stands for revision.  
rev 選項代表版本。

Each time a signature is updated or changed, the revision number changes.  
每次簽名被更新或更改時，版本號會改變。

Here, the number 1 means it's the first version of the signature.  
這裡的數字 1 表示這是簽名的第一個版本。

**Introduction to Suricata**  
**Suricata 介紹**

"Suricata" is an open-source intrusion detection system, intrusion prevention system, and network analysis tool.  
"Suricata"是一個開源的入侵偵測系統、入侵預防系統和網路分析工具。

**Suricata features**  
**Suricata 功能**

There are three main ways Suricata can be used:  
Suricata 可以以三種主要方式使用：

-   Intrusion detection system (IDS): As a network-based IDS, Suricata can monitor network traffic and alert on suspicious activities and intrusions.  
    入侵偵測系統（IDS）：作為網路型 IDS，Suricata 可以監控網路流量並對可疑活動和入侵發出警報。

    Suricata can also be set up as a host-based IDS to monitor the system and network activities of a single host like a computer.  
    Suricata 也可以設置為主機型 IDS，監控單一主機（如電腦）的系統和網路活動。

-   Intrusion prevention system (IPS): Suricata can also function as an intrusion prevention system (IPS) to detect and block malicious activity and traffic.  
    入侵預防系統（IPS）：Suricata 也可以作為入侵預防系統（IPS），來偵測並阻止惡意活動和流量。

    Running Suricata in IPS mode requires additional configuration such as enabling IPS mode.  
    在 IPS 模式下運行 Suricata 需要額外的配置，例如啟用 IPS 模式。

-   Network security monitoring (NSM): In this mode, Suricata helps keep networks safe by producing and saving relevant network logs.  
    網路安全監控（NSM）：在這個模式下，Suricata 通過生成並保存相關的網路日誌來幫助保持網路安全。

    Suricata can analyze live network traffic, existing packet capture files, and create and save full or conditional packet captures.  
    Suricata 可以分析即時網路流量、現有的封包擷取檔案，並創建和保存完整或條件性的封包擷取。

    This can be useful for forensics, incident response, and for testing signatures.  
    這對於法醫分析、事件回應以及測試簽名都非常有用。

    For example, you can trigger an alert and capture the live network traffic to generate traffic logs, which you can then analyze to refine detection signatures.  
    例如，你可以觸發警報並擷取即時網路流量來生成流量日誌，然後你可以分析這些日誌來細化偵測簽名。

**Rules**  
**規則**

Rules or signatures are used to identify specific patterns, behavior, and conditions of network traffic that might indicate malicious activity.  
規則或簽名用於識別可能表明惡意活動的網路流量的特定模式、行為和條件。

The terms rule and signature are often used interchangeably in Suricata.  
在 Suricata 中，規則和簽名這兩個術語常常互換使用。

Security analysts use signatures, or patterns associated with malicious activity, to detect and alert on specific malicious activity.  
安全分析師使用簽名或與惡意活動相關的模式來偵測並對特定的惡意活動發出警報。

Rules can also be used to provide additional context and visibility into systems and networks, helping to identify potential security threats or vulnerabilities.  
規則還可以用來提供系統和網路的額外上下文和可見性，幫助識別潛在的安全威脅或漏洞。

Suricata uses signatures analysis, which is a detection method used to find events of interest.  
Suricata 使用簽名分析，這是一種用來尋找感興趣事件的偵測方法。

Signatures consist of three components:  
簽名由三個組成部分構成：

-   Action: The first component of a signature.  
    動作：簽名的第一個組成部分。

    It describes the action to take if network or system activity matches the signature.  
    它描述了當網路或系統活動匹配簽名時應採取的行動。

    Examples include: alert, pass, drop, or reject.  
    範例包括：警報、通過、丟棄或拒絕。

-   Header: The header includes network traffic information like source and destination IP addresses, source and destination ports, protocol, and traffic direction.  
    標頭：標頭包含網路流量資訊，如來源和目的 IP 地址、來源和目的端口、協議和流量方向。

-   Rule options: The rule options provide you with different options to customize signatures.  
    規則選項：規則選項提供不同的選項來自訂簽名。

Rule options have a specific ordering and changing their order would change the meaning of the rule.  
規則選項有特定的順序，改變它們的順序會改變規則的含義。

Note: The terms rule and signature are synonymous.  
注意：規則和簽名這兩個術語是同義的。

Note: Rule order refers to the order in which rules are evaluated by Suricata.  
注意：規則順序是指 Suricata 評估規則的順序。

Rules are processed in the order in which they are defined in the configuration file.  
規則會按照它們在配置檔案中定義的順序進行處理。

However, Suricata processes rules in a different default order: pass, drop, reject, and alert.  
然而，Suricata 以不同的預設順序處理規則：通過、丟棄、拒絕和警報。

Rule order affects the final verdict of a packet especially when conflicting actions such as a drop rule and an alert rule both match on the same packet.  
規則順序會影響封包的最終判斷，尤其是在丟棄規則和警報規則等衝突動作都匹配同一封包時。

**自訂規則**

雖然 Suricata 附帶了預先編寫的規則，但強烈建議你修改或自訂現有的規則，以滿足你的特定安全需求。

沒有一種通用的方法來創建和修改規則。

這是因為每個組織的 IT 基礎設施各不相同。

安全團隊必須根據需求廣泛測試和修改偵測簽名。

Creating custom rules helps to tailor detection and monitoring.  
創建自訂規則有助於量身定制偵測和監控。

Custom rules help to minimize the amount of false positive alerts that security teams receive.  
自訂規則有助於減少安全團隊收到的假陽性警報數量。

It's important to develop the ability to write effective and customized signatures so that you can fully leverage the power of detection technologies.  
發展編寫有效且自訂簽名的能力是很重要的，這樣你才能充分發揮偵測技術的力量。

**配置檔案**

Before detection tools are deployed and can begin monitoring systems and networks, you must properly configure their settings so that they know what to do.  
在部署偵測工具並開始監控系統和網路之前，你必須正確配置其設置，以便它們知道該如何操作。

配置檔案是用來配置應用程式設置的檔案。

配置檔案讓你精確自訂 IDS 如何與你環境中的其他部分互動。

Suricata 的配置檔案是 suricata.yaml，使用 YAML 檔案格式進行語法和結構配置。

**Log files**

There are two log files that Suricata generates when alerts are triggered:  
當警報被觸發時，Suricata 會產生兩個日誌檔案：

-   `eve.json`: The eve.json file is the standard Suricata log file.  
    `eve.json`：eve.json 檔案是 Suricata 的標準日誌檔案。

    This file contains detailed information and metadata about the events and alerts generated by Suricata stored in JSON format.  
    這個檔案包含有關 Suricata 所生成事件和警報的詳細資訊和元資料，並以 JSON 格式儲存。

    For example, events in this file contain a unique identifier called flow_id which is used to correlate related logs or alerts to a single network flow, making it easier to analyze network traffic.  
    例如，這個檔案中的事件包含一個名為 flow_id 的唯一識別碼，這個識別碼用來將相關的日誌或警報與單一網路流量關聯，從而使網路流量的分析更加容易。

    The eve.json file is used for more detailed analysis and is considered to be a better file format for log parsing and SIEM log ingestion.  
    eve.json 檔案用於更詳細的分析，並被認為是更適合用於日誌解析和 SIEM 日誌導入的檔案格式。

-   `fast.log`: The fast.log file is used to record minimal alert information including basic IP address and port details about the network traffic.  
    `fast.log`：fast.log 檔案用來記錄最基本的警報資訊，包括有關網路流量的基本 IP 地址和端口詳細資訊。

    The fast.log file is used for basic logging and alerting and is considered a legacy file format and is not suitable for incident response or threat hunting tasks.  
    fast.log 檔案用於基本的日誌記錄和警報，並被認為是舊版檔案格式，不適用於事件回應或威脅狩獵任務。

The main difference between the eve.json file and the fast.log file is the level of detail that is recorded in each.  
eve.json 檔案和 fast.log 檔案的主要區別在於它們記錄的詳細資訊的層次。

The fast.log file records basic information, whereas the eve.json file contains additional verbose information.  
fast.log 檔案記錄基本資訊，而 eve.json 檔案包含更多冗長的資訊。

簡單回顧一下，這個過程包含三個步驟：

SIEM 工具需要資料才能有效運作。

SIEM 工具必須首先使用日誌導入來收集資料。

日誌導入是將日誌來源的資料收集並匯入 SIEM 工具的過程。

資料來自任何生成日誌資料的來源，例如伺服器。

在日誌導入過程中，SIEM 會創建它所接收到的事件資料的副本，並將其保留在自己的儲存中。

這個副本使得 SIEM 能夠分析和處理資料，而不直接修改原始來源的日誌。

事件資料的收集為安全分析師提供了一個集中式平台，來分析資料並對事件作出回應。

這些事件資料包括認證嘗試、網路活動等。

There are many ways SIEM tools can ingest log data.

手動上傳資料可能效率低下且耗時，因為網路可能包含數千個系統和裝置。

因此，使用幫助收集資料的軟體會更加容易。

A common way that organizations collect log data is to use log forwarders.  
組織收集日誌資料的常見方式是使用日誌轉發器。

Log forwarders are software that automate the process of collecting and sending log data.  
日誌轉發器是自動化收集和發送日誌資料的軟體。

Some operating systems have native log forwarders.  
一些操作系統有內建的日誌轉發器。

如果你使用的操作系統沒有內建日誌轉發器，你需要在裝置上安裝第三方日誌轉發軟體。

安裝後，你需要配置軟體來指定要轉發哪些日誌，以及將其發送到哪裡。

For example, you can configure the logs to be sent to a SIEM tool.  
例如，你可以將日誌配置為發送到 SIEM 工具。

然後，SIEM 工具將處理並正規化這些資料。

這使得資料可以輕鬆搜尋、探索、關聯和分析。

Note: Many SIEM tools utilize their own proprietary log forwarders.  
注意：許多 SIEM 工具使用它們自己的專有日誌轉發器。

SIEM tools can also integrate with open-source log forwarders.

A wildcard is usually symbolized by an asterisk character *.  
萬用字元通常用星號符號*表示。

Wildcards match characters in string values.  
萬用字元匹配字串值中的字元。

In Splunk, the wildcard that you use depends on the command that you are using the wildcard with.  
在 Splunk 中，你使用的萬用字元取決於你與之一起使用的命令。

Wildcards are useful because they can help find events that contain data that is similar but not entirely identical.  
萬用字元非常有用，因為它們可以幫助找到包含相似但不完全相同的資料的事件。

Here is an example of using a wildcard to expand the search results for a search term:  
這是使用萬用字元擴展搜尋結果的範例：

`index=main fail*`

-   `index=main`: This command retrieves events from an index named main.  
    `index=main`：這個命令從名為 main 的索引中檢索事件。

-   `fail*`: The wildcard after fail represents any character.  
    `fail*`：fail 後的萬用字元代表任何字元。

    This tells Splunk to search for all possible endings that contain the term fail.  
    這告訴 Splunk 搜尋所有可能包含 fail 這個術語的結尾。

    This expands the search results to return any event that contains the term fail such as “failed” or “failure”.  
    這擴展了搜尋結果，返回任何包含 fail 術語的事件，如“failed”或“failure”。

Pro tip: Double quotations are used to specify a search for an exact phrase or string.  
專業小技巧：雙引號用來指定精確字串或片語的搜尋。

For example, if you want to only search for events that contain the exact phrase login failure, you can enclose the phrase in double quotations "login failure".  
例如，如果你只想搜尋包含精確片語 login failure 的事件，可以將片語用雙引號"login failure"括起來。

This search will match only events that contain the exact phrase login failure and not other events that contain the words failure or login separately.  
這個搜尋將僅匹配包含精確片語 login failure 的事件，而不會匹配包含 failure 或 login 單獨出現的其他事件。

**Chronicle searches**  
**Chronicle 搜尋**

In Chronicle, you can search for events using the Search field.  
在 Chronicle 中，你可以使用搜尋欄來搜尋事件。

You can also use Procedural Filtering to apply filters to a search to further refine the search results.  
你也可以使用程序過濾來為搜尋加上篩選條件，進一步精練搜尋結果。

For example, you can use Procedural Filtering to include or exclude search results that contain specific information relating to an event type or log source.  
例如，你可以使用程序過濾來包含或排除包含特定事件類型或日誌來源的搜尋結果。

There are two types of searches you can perform to find events in Chronicle, a Unified Data Model (UDM) Search or a Raw Log Search.  
在 Chronicle 中，你可以執行兩種類型的搜尋來尋找事件，分別是統一資料模型（UDM）搜尋或原始日誌搜尋。

**Unified Data Model (UDM) Search**  
**統一資料模型（UDM）搜尋**

The UDM Search is the default search type used in Chronicle.  
UDM 搜尋是 Chronicle 中預設的搜尋類型。

You can perform a UDM search by typing your search, clicking on “Search,” and selecting “UDM Search.”  
你可以透過輸入搜尋條件、點擊“搜尋”並選擇“UDM 搜尋”來執行 UDM 搜尋。

Through a UDM Search, Chronicle searches security data that has been ingested, parsed, and normalized.  
通過 UDM 搜尋，Chronicle 搜尋已經導入、解析並正規化的安全資料。

A UDM Search retrieves search results faster than a Raw Log Search because it searches through indexed and structured data that’s normalized in UDM.  
UDM 搜尋比原始日誌搜尋更快速，因為它搜尋的是經過索引和結構化的正規化資料。

A UDM Search retrieves events formatted in UDM and these events contain UDM fields.  
UDM 搜尋會檢索以 UDM 格式化的事件，這些事件包含 UDM 欄位。

There are many different types of UDM fields that can be used to query for specific information from an event.  
有許多不同類型的 UDM 欄位可以用來從事件中查詢特定的資訊。

Discussing all of these UDM fields is beyond the scope of this reading, but you can learn more about UDM fields by exploring "Chronicle's UDM field list".  
討論所有這些 UDM 欄位超出了這篇閱讀的範圍，但你可以通過探索「Chronicle 的 UDM 欄位清單」來了解更多關於 UDM 欄位的資訊。

Know that all UDM events contain a set of common fields including:  
請注意，所有的 UDM 事件都包含一組共同的欄位，包括：

Entities: Entities are also known as nouns.  
實體：實體也被稱為名詞。

All UDM events must contain at least one entity.  
所有的 UDM 事件必須至少包含一個實體。

This field provides additional context about a device, user, or process that’s involved in an event.  
此欄位提供有關裝置、使用者或在事件中涉及的過程的額外上下文。

For example, a UDM event that contains entity information includes the details of the origin of an event such as the hostname, the username, and IP address of the event.  
例如，包含實體資訊的 UDM 事件會包括事件起源的細節，如主機名稱、使用者名稱和事件的 IP 位址。

-   Event metadata: This field provides a basic description of an event, including what type of event it is, timestamps, and more.  
    事件元資料：此欄位提供事件的基本描述，包括事件類型、時間戳記等。

-   Network metadata: This field provides information about network-related events and protocol details.  
    網路元資料：此欄位提供有關網路相關事件和協議細節的資訊。

-   Security results: This field provides the security-related outcome of events.  
    安全結果：此欄位提供事件的安全相關結果。

    An example of a security result can be an antivirus software detecting and quarantining a malicious file by reporting "virus detected and quarantined."  
    安全結果的範例可以是防毒軟體偵測並隔離惡意檔案，並報告「病毒已偵測並已隔離」。

Here’s an example of a simple UDM search that uses the event metadata field to locate events relating to user logins:  
這裡有一個簡單的 UDM 搜尋範例，使用事件元資料欄位來定位與使用者登入相關的事件：

`metadata.event_type = “USER_LOGIN”`

-   `metadata.event_type = “USER_LOGIN”`: This UDM field metadata.event_type contains information about the event type.  
    `metadata.event_type = “USER_LOGIN”`：這個 UDM 欄位 metadata.event_type 包含有關事件類型的資訊。

    This includes information like timestamp, network connection, user authentication, and more.  
    這包括像是時間戳記、網路連線、使用者認證等資訊。

    Here, the event type specifies USER_LOGIN, which searches for events relating to authentication.  
    在這裡，事件類型指定為 USER_LOGIN，這是搜尋與認證相關的事件。

Using just the metadata fields, you can quickly start searching for events.  
僅使用元資料欄位，你就可以快速開始搜尋事件。

As you continue practicing searching in Chronicle using UDM Search, you will encounter more fields.  
當你繼續在 Chronicle 中使用 UDM 搜尋進行練習時，你將會遇到更多的欄位。

Try using these fields to form specific searches to locate different events.  
試著使用這些欄位來構建具體的搜尋，以定位不同的事件。

**Raw Log Search**  
**原始日誌搜尋**

If you can't find the information you are searching for through the normalized data, using a Raw Log Search will search through the raw, unparsed logs.  
如果你無法透過正規化資料找到所需的資訊，使用原始日誌搜尋將搜尋未解析的原始日誌。

You can perform a Raw Log Search by typing your search, clicking on “Search,” and selecting “Raw Log Search.”  
你可以透過輸入搜尋條件、點擊「搜尋」並選擇「原始日誌搜尋」來執行原始日誌搜尋。

Because it is searching through raw logs, it takes longer than a structured search.  
由於它是在搜尋原始日誌，這會比結構化搜尋花費更多時間。

In the Search field, you can perform a Raw Log Search by specifying information like usernames, filenames, hashes, and more.  
在搜尋欄位中，你可以透過指定像是使用者名稱、檔案名稱、雜湊值等資訊來執行原始日誌搜尋。

Chronicle will retrieve events that are associated with the search.  
Chronicle 將檢索與該搜尋相關的事件。

Pro tip: Raw Log Search supports the use of regular expressions, which can help you narrow down a search to match on specific patterns.  
專業小技巧：原始日誌搜尋支援使用正規表示式，這可以幫助你將搜尋範圍縮小到符合特定模式的結果。

SIEM tools like Splunk and Chronicle have their own methods for searching and retrieving event data.  
像 Splunk 和 Chronicle 這樣的 SIEM 工具有各自的方法來搜尋和檢索事件資料。

作為安全分析師，了解如何運用這些工具來快速且有效地找到所需的資訊是非常重要的。

This will allow you to explore data in ways that support detecting threats, as well as rapidly responding to security incidents.  
這將讓你能夠以支持偵測威脅的方式探索資料，並快速回應安全事件。

**Terms and definitions from Course 6, Module 4**  
**來自課程 6，模塊 4 的術語和定義**

**Anomaly-based analysis:** A detection method that identifies abnormal behavior  
**基於異常的分析：** 一種偵測方法，用來識別異常行為

**Array:** A data type that stores data in a comma-separated ordered list  
**陣列：** 一種資料類型，用來將資料儲存在以逗號分隔的有序清單中

**Common Event Format (CEF):** A log format that uses key-value pairs to structure data and identify fields and their corresponding values  
**通用事件格式（CEF）：** 一種日誌格式，使用鍵值對來結構化資料並識別欄位及其對應的值

**Configuration file:** A file used to configure the settings of an application  
**配置檔案：** 用來設定應用程式設定的檔案

**Endpoint:** Any device connected on a network  
**端點：** 任何連接到網路的裝置

**Endpoint detection and response (EDR):** An application that monitors an endpoint for malicious activity  
**端點偵測與回應（EDR）：** 一種應用程式，用來監控端點是否有惡意活動

**False positive:** An alert that incorrectly detects the presence of a threat  
**假陽性：** 一種錯誤檢測到威脅存在的警示

**Host-based intrusion detection system (HIDS):** An application that monitors the activity of the host on which it’s installed  
**主機型入侵偵測系統（HIDS）：** 一種應用程式，用來監控其安裝主機的活動

**Intrusion detection systems (IDS):** An application that monitors system activity and alerts on possible intrusions  
**入侵偵測系統（IDS）：** 一種應用程式，用來監控系統活動並對可能的入侵發出警示

**Key-value pair:** A set of data that represents two linked items: a key, and its corresponding value  
**鍵值對：** 一組資料，代表兩個相關聯的項目：一個鍵及其對應的值

**Log:** A record of events that occur within an organization’s systems  
**日誌：** 記錄在組織系統中發生事件的檔案

**Log analysis:** The process of examining logs to identify events of interest  
**日誌分析：** 檢查日誌以識別感興趣事件的過程

**Log management:** The process of collecting, storing, analyzing, and disposing of log data  
**日誌管理：** 收集、儲存、分析和處理日誌資料的過程

**Logging:** The recording of events occurring on computer systems and networks  
**日誌紀錄：** 記錄在電腦系統和網路中發生的事件

**Network-based intrusion detection system (NIDS):** An application that collects and monitors network traffic and network data  
**網路型入侵偵測系統（NIDS）：** 一種應用程式，用來收集和監控網路流量及網路資料

**Object:** A data type that stores data in a comma-separated list of key-value pairs  
**物件：** 一種資料類型，將資料儲存在以逗號分隔的鍵值對清單中

**Search Processing Language (SPL):** Splunk’s query language  
**搜尋處理語言（SPL）：** Splunk 的查詢語言

**Security information and event management (SIEM):** An application that collects and analyzes log data to monitor critical activities in an organization  
**安全資訊與事件管理（SIEM）：** 一種收集並分析日誌資料來監控組織內關鍵活動的應用程式

**Signature:** A pattern that is associated with malicious activity  
**簽名：** 與惡意活動相關聯的模式

**Signature analysis:** A detection method used to find events interest  
**簽名分析：** 一種用來尋找感興趣事件的偵測方法

**Suricata:** An open-source intrusion detection system, intrusion prevention system, and network analysis tool  
**Suricata：** 一個開源的入侵偵測系統、入侵防護系統及網路分析工具

**Telemetry:** The collection and transmission of data for analysis  
**遙測：** 用於分析的資料收集與傳輸

**Wildcard:** A special character that can be substituted with any other character  
**萬用字元：** 一個特殊字符，可以被任何其他字符取代

**YARA-L:** A computer language used to create rules for searching through ingested log data  
**YARA-L：** 一種用來創建規則以搜尋已導入日誌資料的程式語言

**Zero-day:** An exploit that was previously unknown  
**零日漏洞：** 之前未知的漏洞利用
