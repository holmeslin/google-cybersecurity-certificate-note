### The importance of network traffic flows 網絡流量的重要性

In many organizations, network communication travels over multiple networks in different countries and across different devices.

在許多組織中，網絡通信會穿越多個國家的不同網絡，並且通過不同的設備。

Data can get unintentionally sent and stored in insecure places, like personal email inboxes or cloud storage platforms.

數據可能會不小心被發送並儲存在不安全的地方，如個人電子郵件收件箱或雲端儲存平台。

Users trust that their data is safely and securely sent and stored.

用戶信任他們的數據會被安全地發送和儲存。

And it's the job of security professionals like you to help protect these communications in transit and at rest.

而像你這樣的安全專業人員的工作就是幫助保護這些在傳輸過程中和靜止時的通信。

Previously, you may recall learning how to identify and secure critical assets through security controls like data classification and encryption.

你可能記得先前學過如何通過像數據分類和加密這樣的安全控制來識別並保護關鍵資產。

Coming up, we'll expand on this topic and examine how network traffic analysis can be used to monitor network activity and identify potential malicious activity.

接下來，我們將擴展這個話題，並探討如何使用網絡流量分析來監控網絡活動並識別潛在的惡意活動。

So what is network traffic? Network traffic is the amount of data that moves across a network.

那麼什麼是網絡流量呢？網絡流量是指在網絡中流動的數據量。

While network data is the data that's transmitted between devices on a network.

網絡數據是指在網絡上設備之間傳輸的數據。

Depending on the size of a network, there can be a huge volume of network traffic at any given moment.

根據網絡的大小，在任何給定的時刻，都可能會有大量的網絡流量。

For example, in a large, multinational organization, there may be thousands of employees sending and receiving emails at any given time.

例如，在一家大型的跨國組織中，可能會有數千名員工在任何時候發送和接收電子郵件。

That's a lot of network traffic.

這是大量的網絡流量。

With such large volumes of traffic being produced, how do you know what's normal behavior, or what's unusual and requires investigation as a potential security incident?  
在如此大量的流量產生下，如何知道什麼是正常行為，或者什麼是不正常的並需要作為潛在安全事件進行調查呢？

想像一下，在你正常上班的路上，突然被意外的交通堵塞困住。

當你行駛時，你意識到是某些不尋常的事情造成了交通堵塞，比如一場小型車輛碰撞，導致預期的交通流量變慢。

在道路上，我們根據通勤經驗對交通流量有一定的預期。

高峰時段的交通模式，如早晚高峰是正常且預期的，而在非高峰時段的異常交通則顯示出有不預期的事情發生了，比如車輛碰撞。

網絡流量的運作方式也相同。

通過了解數據應如何在網絡中流動，你可以對預期的網絡流量流向有更好的理解。

了解什麼是正常的，你就能輕鬆發現什麼是異常的。

We can detect traffic abnormalities through observation to spot indicators of compromise, also known as IoC, which are observable evidence that suggests signs of a potential security incident.

我們可以通過觀察來偵測流量異常，以發現妥協指標，也稱為 IoC，這是可以觀察到的證據，顯示出潛在安全事件的跡象。

以數據外洩為例，數據外洩是指未經授權的數據從系統中傳輸出去。

### Maintain awareness with network monitoring 透過網絡監控保持警覺

Network communication can be noisy! Events like sending an email, streaming a video, or visiting a website all produce network communications in the form of network traffic and network data.

網絡通信可能很嘈雜！像發送電子郵件、串流視頻或訪問網站這樣的事件，都會以網絡流量和網絡數據的形式產生網絡通信。

As a reminder, network traffic is the amount of data that moves across a network.

提醒一下，網絡流量是指在網絡中流動的數據量。

It can also include the type of data that is transferred, such as HTTP.

它也可以包括傳輸的數據類型，如 HTTP。

Network data is the data that's transmitted between devices on a network.

網絡數據是指在網絡上設備之間傳輸的數據。

Network monitoring is essential in maintaining situational awareness of any activity on a network.

網絡監控對於保持對網絡活動的情境感知至關重要。

By collecting and analyzing network traffic, organizations can detect suspicious network activity.

通過收集和分析網絡流量，組織可以偵測到可疑的網絡活動。

But before networks can be monitored, you must know exactly what to monitor.

但在監控網絡之前，你必須確切了解應該監控什麼。

In this reading, you'll learn more about the importance of network monitoring, ways to monitor your network, and network monitoring tools.

在這篇閱讀中，你將深入了解網絡監控的重要性、如何監控你的網絡以及網絡監控工具。

**Know your network**  
**了解你的網絡**

As you’ve learned, networks connect devices, and devices then communicate and exchange data using network protocols.

正如你所學到的，網絡將設備連接起來，然後設備使用網絡協議進行通信並交換數據。

Network communications provide information about connections such as source and destination IP addresses, amount of data transferred, date and time, and more.

網絡通信提供有關連接的信息，如來源和目標 IP 地址、傳輸的數據量、日期和時間等。

This information can be valuable for security professionals when developing a baseline of normal or expected behavior.

這些信息對於安全專業人員在建立正常或預期行為基準時非常有價值。

Line graph displaying a baseline running through the middle of data peaks.

基準線圖顯示基準線穿過數據峰值的中間。

A baseline is a reference point that’s used for comparison.

基準線是用來作比較的參考點。

You've probably encountered or used baselines at some point.

你可能在某個時候遇到過或使用過基準線。

For example, a grocery amount for a personal budget is an example of a baseline that can be used to help identify any patterns or changes in spending habits.

例如，個人預算中的食品費用就是一個基準線的例子，可以用來幫助識別消費習慣中的任何模式或變化。

In security, baselines help establish a standard of expected or normal behavior for systems, devices, and networks.

在安全領域，基準線有助於為系統、設備和網絡建立預期或正常行為的標準。

Essentially, by knowing the baseline of normal network behavior, you'll be better able to identify abnormal network behavior.

本質上，通過了解正常網絡行為的基準線，你將能更好地識別異常的網絡行為。

**Monitor your network**  
**監控你的網絡**

Once you’ve determined a baseline, you can monitor a network to identify any deviations from that baseline.

一旦你確定了基準線，你就可以監控網絡，識別任何偏離基準線的情況。

Monitoring involves examining network components to detect unusual activities, such as large and unusual data transfers.

監控涉及檢查網絡組件，以偵測不尋常的活動，如大量且異常的數據傳輸。

Here are examples of network components that can be monitored to detect malicious activity:  
以下是可以監控的網絡組件示例，用於偵測惡意活動：

**Flow analysis**  
**流量分析**

Flow refers to the movement of network communications and includes information related to packets, protocols, and ports.

流量指的是網絡通信的流動，並包含與封包、協議和端口相關的信息。

Packets can travel to ports, which receive and transmit communications.

封包可以傳送到端口，端口接收和傳送通信。

Ports are often, but not always, associated with network protocols.

端口通常與網絡協議相關，但並不總是如此。

For example, port 443 is commonly used by HTTPS which is a protocol that provides website traffic encryption.

例如，端口 443 通常由 HTTPS 協議使用，它是一種提供網站流量加密的協議。

However, malicious actors can use protocols and ports that are not commonly associated to maintain communications between the compromised system and their own machine.

然而，惡意行為者可以使用不常見的協議和端口來維持受感染系統與他們自己機器之間的通信。

These communications are what’s known as command and control (C2), which are the techniques used by malicious actors to maintain communications with compromised systems.

這些通信被稱為指揮與控制（C2），是惡意行為者用來與受感染系統維持通信的技術。

For example, malicious actors can use HTTPS protocol over port 8088 as opposed to its commonly associated port 443 to communicate with compromised systems.

例如，惡意行為者可以使用 HTTPS 協議透過端口 8088，而不是常見的端口 443，與受感染系統通信。

Organizations must know which ports should be open and approved for connections, and watch out for any mismatches between ports and their associated protocols.

組織必須知道哪些端口應該開放並批准連接，並警惕端口與其相關協議之間的任何不匹配。

**Packet payload information**  
**封包有效載荷信息**

Network packets contain components related to the transmission of the packet.

網絡封包包含與封包傳輸相關的組件。

This includes details like source and destination IP address, and the packet payload information, which is the actual data that’s transmitted.

這包括像來源和目標 IP 地址，以及封包有效載荷信息，這是實際傳輸的數據。

Often, this data is encrypted and requires decryption for it to be readable.

通常，這些數據是加密的，需要解密才能閱讀。

Organizations can monitor the payload information of packets to uncover unusual activity, such as sensitive data transmitting outside of the network, which could indicate a possible data exfiltration attack.

組織可以監控封包的有效載荷信息，發現異常活動，例如敏感數據傳輸到網絡外部，這可能表示發生了數據外洩攻擊。

**Temporal patterns**  
**時間模式**

Network packets contain information relating to time.

網絡封包包含與時間相關的信息。

This information is useful in understanding time patterns.

這些信息對於了解時間模式非常有用。

For example, a company operating in North America experiences bulk traffic flows between 9 a.m. to 5 p.m., which is the baseline of normal network activity.

例如，一家在北美運營的公司，其流量在上午 9 點到下午 5 點之間較大，這是正常網絡活動的基準線。

If large volumes of traffic are suddenly outside of the normal hours of network activity, then this is considered off baseline and should be investigated.

如果大量流量突然出現在網絡活動的正常時間之外，那麼這被視為偏離基準線，應該進行調查。

Through network monitoring, organizations can promptly detect network intrusions and work to prevent them from happening by securing network components.

通過網絡監控，組織可以及時偵測到網絡入侵，並通過保護網絡組件來防止其發生。

**Protect your network**  
**保護你的網絡**

In this program, you’ve learned about security operations centers (SOC) and their role in monitoring systems against security threats and attacks.

在這個課程中，你已經學習了安全運營中心（SOC）及其在監控系統對抗安全威脅和攻擊中的角色。

Organizations may deploy a network operations center (NOC), which is an organizational unit that monitors the performance of a network and responds to any network disruption, such as a network outage.

組織可能會部署網絡運營中心（NOC），這是一個監控網絡性能並對任何網絡中斷（如網絡故障）做出反應的組織單位。

While a SOC is focused on maintaining the security of an organization through detection and response, a NOC is responsible for maintaining network performance, availability, and uptime.

SOC 專注於通過偵測和回應來維護組織的安全，而 NOC 則負責維護網絡性能、可用性和正常運行時間。

An analyst monitors system activity on multiple computer screens.

分析師在多個電腦屏幕上監控系統活動。

Security analysts monitor networks to identify any signs of potential security incidents known as indicators of compromise (IoC) and protect networks from threats or attacks.

安全分析師監控網絡，識別任何潛在安全事件的跡象，這些跡象被稱為妥協指標（IoC），並保護網絡免受威脅或攻擊。

To do this, they must understand the environment that network communications travel through so that they can identify deviations in network traffic.

為此，他們必須了解網絡通信所經過的環境，這樣才能識別網絡流量中的偏差。

**Network monitoring tools**  
**網絡監控工具**

Network monitoring can be automated or performed manually.

網絡監控可以自動化或手動進行。

Some common network monitoring tools can include:  
一些常見的網絡監控工具包括：

-   Intrusion detection systems (IDS) monitor system activity and alert on possible intrusions.

    入侵偵測系統（IDS）監控系統活動並對可能的入侵發出警報。
    An IDS will detect and alert on the deviations you’ve configured it to detect.

    IDS 會偵測並對你配置它來偵測的偏差發出警報。
    Most commonly, IDS tools will monitor the content of packet payload to detect patterns associated with threats such as malware or phishing attempts.

    最常見的，IDS 工具會監控封包有效載荷的內容，以偵測與威脅相關的模式，如惡意軟件或釣魚嘗試。

-   Network protocol analyzers, also known as packet sniffers, are tools designed to capture and analyze data traffic within a network.

    網絡協議分析儀，也稱為封包嗅探器，是用來捕獲和分析網絡內數據流量的工具。
    They can be used to analyze network communications manually in detail.

    它們可以用來手動詳細分析網絡通信。
    Examples include tools such as tcpdump and Wireshark, which can be used by security professionals to record network communications through packet captures.

    範例如 tcpdump 和 Wireshark 這些工具，安全專業人員可以使用它們通過封包捕獲來記錄網絡通信。

Packet captures can then be investigated to identify potentially malicious activity.

隨後，可以對封包捕獲進行調查，以識別可能的惡意活動。

Monitoring and protecting networks from intrusions and attacks are key responsibilities of security professionals.

監控並保護網絡免受入侵和攻擊是安全專業人員的主要職責。

基準線通過揭示常見模式來提供理解網絡流量的方法，這有助於識別與預期流量模式的任何偏差。

Tools like intrusion detection systems and network protocol analyzers support efforts in monitoring network activities.

像入侵偵測系統和網絡協議分析儀這樣的工具支持網絡活動監控的工作。

### Data exfiltration attacks 數據外洩攻擊

Monitoring network traffic helps security professionals detect, prevent, and respond to attacks.

監控網絡流量幫助安全專業人員偵測、防止和回應攻擊。

In my experience as a security professional, monitoring for deviations from typical network traffic patterns has yielded big results.

根據我作為安全專業人員的經驗，監控典型網絡流量模式的偏差已經帶來了顯著的結果。

Even if information is encrypted, monitoring network traffic is still important for security purposes.

即使信息已加密，監控網絡流量對於安全目的仍然非常重要。

Let's discuss how the detection and response process might work in a data exfiltration attack.

讓我們來討論在數據外洩攻擊中，偵測和回應過程可能是如何運作的。

First, we'll outline the attacker's perspective.

首先，我們將概述攻擊者的視角。

Before attackers can perform data exfiltration, they'll need to gain initial access into a network and computer system.

在攻擊者能夠進行數據外洩之前，他們需要先獲得對網絡和計算機系統的初步訪問。

Now, an attacker has successfully gained access to their device.

現在，攻擊者已經成功獲得了對其設備的訪問。

在獲得系統的初步訪問後，攻擊者不會就此停止。

The goal for attackers is to maintain access in the environment and avoid being detected for as long as possible.

攻擊者的目標是維持在環境中的訪問並盡可能避免被偵測到。

To do this, they'll perform a tactic known as lateral movement, or pivoting.

為了達到這一目標，他們會執行一種稱為側向移動（lateral movement）或樞紐操作（pivoting）的策略。

這是指他們花時間探索網絡，目的是擴展並保持對網絡上其他系統的訪問。

當攻擊者在網絡中進行樞紐操作時，他們會探索環境，識別有價值的資產，如專有代碼、個人身份信息（如姓名和地址）或財務記錄等敏感數據。

他們會通過搜尋網絡檔案共享、內聯網網站、代碼庫等位置來進行。

After the attacker identifies the assets of value, they'll need to collect, package, and prepare the data for exfiltration outside of the organization's network and into the attacker's hands.

當攻擊者識別出有價值的資產後，他們需要收集、打包並準備數據以便從組織的網絡外洩，並交到攻擊者手中。

他們可能會通過減少數據大小來做到這一點。

這有助於攻擊者隱藏被竊取的數據並繞過安全控制。

Finally, the attacker will exfiltrate the data to their destination of choice.

最後，攻擊者會將數據外洩到他們選擇的目的地。

There are many ways to do this.

有很多方法可以做到這一點。

For example, attackers can email the stolen data to themselves using the compromised email account.

例如，攻擊者可以利用被入侵的電子郵件帳戶將竊取的數據發送到自己的郵箱。

成功入侵網絡的攻擊者可以在一段時間內不被察覺。

It's important that security teams monitor network activity to identify any suspicious activity that can indicate a compromise.

安全團隊需要監控網絡活動，以識別任何可疑活動，這些活動可能表明已經遭受妥協。

For example, multiple user logins coming from IP addresses outside of the network should be investigated.

例如，來自網絡外部 IP 地址的多次用戶登錄應該進行調查。

早些時候，你學習了如何通過資產清單和安全控制來識別、分類和保護資產。

最後，如果數據外洩攻擊成功，安全團隊必須偵測並停止數據外洩。

有很多方法可以阻止這類攻擊。

**How network protocol analyzers work**  
**網絡協議分析儀的工作原理**

Network protocol analyzers use both software and hardware capabilities to capture network traffic and display it for security analysts to examine and analyze.

網絡協議分析儀利用軟硬體能力捕獲網絡流量，並將其顯示給安全分析師進行檢查和分析。

Here’s how:  
以下是它的運作方式：

-   First, packets must be collected from the network via the Network Interface Card (NIC), which is hardware that connects computers to a network, like a router.

    首先，必須通過網絡介面卡（NIC）從網絡中收集封包，NIC 是將計算機連接到網絡的硬件，如路由器。

    NICs receive and transmit network traffic, but by default they only listen to network traffic that’s addressed to them.

    NIC 接收和傳送網絡流量，但默認情況下，它們只聆聽發送給自己的網絡流量。

    To capture all network traffic that is sent over the network, a NIC must be switched to a mode that has access to all visible network data packets.

    若要捕獲網絡上傳送的所有網絡流量，NIC 必須切換到能夠訪問所有可見網絡數據封包的模式。

    In wireless interfaces this is often referred to as monitoring mode, and in other systems it may be called promiscuous mode.

    在無線接口中，這通常稱為監控模式，而在其他系統中則可能稱為混雜模式。

    This mode enables the NIC to have access to all visible network data packets, but it won’t help analysts access all packets across a network.

    這種模式使 NIC 能夠訪問所有可見的網絡數據封包，但它不會幫助分析師訪問整個網絡中的所有封包。

    A network protocol analyzer must be positioned in an appropriate network segment to access all traffic between different hosts.

    網絡協議分析儀必須放置在適當的網絡段中，以便訪問不同主機之間的所有流量。

-   The network protocol analyzer collects the network traffic in raw binary format.

    網絡協議分析儀以原始二進制格式收集網絡流量。

    Binary format consists of 0s and 1s and is not as easy for humans to interpret.

    二進制格式由 0 和 1 組成，人類很難直接解釋。

    The network protocol analyzer takes the binary and converts it so that it’s displayed in a human-readable format, so analysts can easily read and understand the information.

    網絡協議分析儀將二進制轉換為人類可讀的格式，讓分析師可以輕鬆閱讀並理解信息。

Note: Enabling promiscuous can expose your device to potential attacks because it allows sensitive information like passwords and other confidential data to be captured.

註：啟用混雜模式可能會使你的設備暴露於潛在攻擊，因為這允許像密碼和其他機密數據這樣的敏感信息被捕獲。

It's important to use tools that operate in promiscuous mode responsibly and with caution.

使用在混雜模式下運行的工具時，必須負責任且小心謹慎。

**Capturing packets**  
**捕獲封包**

Packet sniffing is the practice of capturing and inspecting data packets across a network.

封包嗅探是捕獲和檢查網絡上數據封包的過程。

A packet capture (p-cap) is a file containing data packets intercepted from an interface or network.

封包捕獲（p-cap）是一個文件，包含從接口或網絡攔截的數據封包。

Packet captures can be viewed and further analyzed using network protocol analyzers.

封包捕獲可以使用網絡協議分析儀來查看和進一步分析。

For example, you can filter packet captures to only display information that's most relevant to your investigation, such as packets sent from a specific IP address.

例如，你可以篩選封包捕獲，只顯示與你的調查最相關的信息，例如來自特定 IP 地址的封包。

Note: Using network protocol analyzers to intercept and examine private network communications without permission is considered illegal in many places.

註：在未經許可的情況下使用網絡協議分析儀攔截和檢查私密網絡通信在許多地方被視為非法。

P-cap files can come in many formats depending on the packet capture library that’s used.

默認情況下，tcpdump 不會打印出封包的所有信息。

This option, which stands for verbose, lets you control how much packet information you want tcpdump to print out.

這個選項，代表詳細模式，讓你控制 tcpdump 要打印多少封包信息。

There are three levels of verbosity you can use depending on how much packet information you want tcpdump to print out.

你可以根據需要打印多少封包信息，使用三個詳細級別。

The levels are -v, -vv, and -vvv.

這些級別分別是 -v、-vv 和 -vvv。

The level of verbosity increases with each added v.

每增加一個 v，詳細級別就會提高。

The verbose option can be helpful if you’re looking for packet information like the details of a packet’s IP header fields.

如果你正在尋找封包信息，如封包 IP 標頭欄位的細節，詳細模式選項會很有幫助。

Here’s an example of a tcpdump command that reads the packetcapture.pcap file with verbosity:  
以下是使用詳細模式讀取 packetcapture.pcap 文件的 tcpdump 命令範例：

`sudo tcpdump -r packetcapture.pcap -v`

**`-c`**  
**`-c`**

The -c option stands for count.

-c 選項代表計數。

This option lets you control how many packets tcpdump will capture.

這個選項讓你控制 tcpdump 將捕獲多少個封包。

For example, specifying -c 1 will only print out one single packet, whereas -c 10 prints out 10 packets.

例如，指定 -c 1 只會打印出一個封包，而 -c 10 則會打印出 10 個封包。

This example is telling tcpdump to only capture the first three packets it sniffs from any network interface:  
這個範例告訴 tcpdump 只捕獲它從任何網絡介面嗅探到的前三個封包：

`sudo tcpdump -i any -c 3`

**`-n`**  
**`-n`**

By default, tcpdump will perform name resolution.

默認情況下，tcpdump 會執行名稱解析。

This means that tcpdump automatically converts IP addresses to names.

這意味著 tcpdump 自動將 IP 地址轉換為名稱。

It will also resolve ports to commonly associated services that use these ports.

它還會將端口解析為常見的與這些端口相關聯的服務。

This can be problematic because tcpdump isn’t always accurate in name resolution.

這可能會造成問題，因為 tcpdump 在名稱解析方面並不總是準確的。

For example, tcpdump can capture traffic from port 80 and automatically translates port 80 to HTTP in the output.

例如，tcpdump 可以捕獲來自端口 80 的流量，並在輸出中將端口 80 自動轉換為 HTTP。

However, this is misleading because port 80 isn’t always going to be using HTTP; it could be using a different protocol.

然而，這是誤導性的，因為端口 80 不總是使用 HTTP；它也可能使用其他協議。

Additionally, name resolution uses what’s known as a reverse DNS lookup.

此外，名稱解析使用的是所謂的反向 DNS 查詢。

A reverse DNS lookup is a query that looks for the domain name associated with an IP address.

反向 DNS 查詢是一種查詢，用來尋找與 IP 地址相關聯的域名。

If you perform a reverse DNS lookup on an attacker’s system, they might be alerted that you are investigating them through their DNS records.

如果你對攻擊者的系統執行反向 DNS 查詢，他們可能會被警告你正在通過他們的 DNS 記錄調查他們。

Using the -n flag disables this automatic mapping of numbers to names and is considered to be best practice when sniffing or analyzing traffic.

使用 -n 旗標禁用自動將數字映射到名稱，這在嗅探或分析流量時被認為是最佳做法。

Using -n will not resolve hostnames, whereas -nn will not resolve both hostnames or ports.

使用 -n 不會解析主機名，而 -nn 則不會解析主機名或端口。

Here’s an example of a tcpdump command that reads the packetcapture.pcap file with verbosity and disables name resolution:  
這是使用詳細模式讀取 packetcapture.pcap 文件並禁用名稱解析的 tcpdump 命令範例：

`sudo tcpdump -r packetcapture.pcap -v -n`

Pro tip: You can combine options together.

專業提示：你可以將選項組合在一起。

For example, -v and -n can be combined as -vn.

例如，-v 和 -n 可以組合為 -vn。

But, if an option accepts a parameter right after it like -c 1 or -r capture.pcap then you can’t combine other options to it.

但是，如果一個選項後面跟著一個參數，例如 -c 1 或 -r capture.pcap，那麼你不能將其他選項與其組合。

**Expressions**  
**表達式**

Using filter expressions in tcpdump commands is also optional, but knowing how and when to use filter expressions can be helpful during packet analysis.

在 tcpdump 命令中使用過濾表達式也是可選的，但了解如何以及何時使用過濾表達式對於封包分析很有幫助。

There are many ways to use filter expressions.

有很多種方法可以使用過濾表達式。

If you want to specifically search for network traffic by protocol, you can use filter expressions to isolate network packets.

如果你想根據協議具體搜索網絡流量，可以使用過濾表達式來隔離網絡封包。

For example, you can filter to find only IPv6 traffic using the filter expression ip6.

例如，你可以使用過濾表達式 ip6 來過濾只包含 IPv6 流量的封包。

You can also use boolean operators like and, or, or not to further filter network traffic for specific IP addresses, ports, and more.

你還可以使用布爾運算符，如 and、or 或 not，來進一步過濾特定 IP 地址、端口等的網絡流量。

The example below reads the packetcapture.pcap file and combines two expressions ip and port 80 using the and boolean operator:  
以下範例讀取 packetcapture.pcap 文件，並使用 and 布爾運算符組合兩個表達式 ip 和 port 80：

`sudo tcpdump -r packetcapture.pcap -n 'ip and port 80'`

Pro tip: You can use single or double quotes to ensure that tcpdump executes all of the expressions.

專業提示：你可以使用單引號或雙引號來確保 tcpdump 執行所有表達式。

You can also use parentheses to group and prioritize different expressions.

你也可以使用括號來分組並優先執行不同的表達式。

Grouping expressions is helpful for complex or lengthy commands.

分組表達式對於複雜或長的命令非常有幫助。

For example, the command ip and (port 80 or port 443) tells tcpdump to prioritize executing the filters enclosed in the parentheses before filtering for IPv4.

例如，命令 ip 和 (port 80 或 port 443) 告訴 tcpdump 在過濾 IPv4 之前優先執行括號中的過濾條件。

**Interpreting output**  
**解釋輸出結果**

Once you run a command to capture packets, tcpdump will print the output of the command as the sniffed packets.

當你執行命令來捕獲封包時，tcpdump 會將命令的輸出作為嗅探到的封包打印出來。

In the output, tcpdump prints one line of text for each packet with each line beginning with a timestamp.

在輸出中，tcpdump 會為每個封包打印一行文本，每行文本以時間戳開始。

Here’s an example of a command and output for a single TCP packet:  
以下是單個 TCP 封包的命令和輸出範例：

`sudo tcpdump -i any -v -c 1`

This command tells tcpdump to capture packets on -i any network interface.

這個命令告訴 tcpdump 捕獲來自 -i any 網絡介面的封包。

The option -v prints out the packet with detailed information and the option -c 1 prints out only one packet.

選項 -v 會打印出封包的詳細信息，選項 -c 1 只會打印出一個封包。

Here is the output of this command:  
這是此命令的輸出結果：

Output of a tcpdump command with labels for the timestamp, source IP, source port, destination IP, and destination port.

tcpdump 命令的輸出，標註時間戳、源 IP、源端口、目標 IP 和目標端口。

-   Timestamp: The output begins with the timestamp, which starts with hours, minutes, seconds, and fractions of a second.

    時間戳：輸出從時間戳開始，時間戳包括小時、分鐘、秒和秒的分數部分。

-   Source IP: The packet’s origin is provided by its source IP address.

    源 IP：封包的來源由其源 IP 地址提供。

-   Source port: This port number is where the packet originated.

    源端口：這個端口號是封包的來源。

-   Destination IP: The destination IP address is where the packet is being transmitted to.

    目標 IP：目標 IP 地址是封包被傳送到的地方。

-   Destination port: This port number is where the packet is being transmitted to.

    目標端口：這個端口號是封包被傳送到的地方。

The remaining output contains details of the TCP connection including flags and sequence number.

剩餘的輸出包含有關 TCP 連接的細節，包括標誌和序列號。

The options information is additional packet information that the -v option has provided.

選項信息是 -v 選項提供的額外封包信息。

### Glossary terms from module 2 模組 2 的術語詞彙

**Terms and definitions from Course 6, Module 2**  
**課程 6, 模組 2 的術語與定義**

**Command and control (C2):** The techniques used by malicious actors to maintain communications with compromised systems  
**指揮與控制 (C2)：** 惡意攻擊者用來與被攻陷系統保持通信的技術

**Command-line interface (CLI):** A text-based user interface that uses commands to interact with the computer  
**命令行界面 (CLI)：** 一種基於文本的用戶界面，通過命令與計算機交互

**Data exfiltration:** Unauthorized transmission of data from a system  
**數據外洩：** 未經授權從系統傳輸數據

**Data packet:** A basic unit of information that travels from one device to another within a network  
**數據封包：** 一個基本的資訊單位，在網絡中從一個設備傳送到另一個設備

**Indicators of compromise (IoC):** Observable evidence that suggests signs of a potential security incident  
**妥協指標 (IoC)：** 可以觀察到的證據，顯示潛在安全事件的跡象

**Internet Protocol (IP):** A set of standards used for routing and addressing data packets as they travel between devices on a network  
**網際網路協議 (IP)：** 用於路由和定址數據封包的標準，確保它們在網絡設備之間傳輸

**Intrusion detection systems (IDS):** An application that monitors system activity and alerts on possible intrusions  
**入侵檢測系統 (IDS)：** 用於監控系統活動並對可能的入侵發出警報的應用程序

**Media Access Control (MAC) Address:** A unique alphanumeric identifier that is assigned to each physical device on a network  
**媒體存取控制 (MAC) 地址：** 分配給網絡中每個物理設備的唯一字母數字識別碼

**National Institute of Standards and Technology (NIST) Incident Response Lifecycle:** A framework for incident response consisting of four phases: Preparation; Detection and Analysis; Containment, Eradication and Recovery; and Post-incident activity  
**國家標準與技術研究院 (NIST) 事件回應生命周期：** 由四個階段組成的事件回應框架：準備；檢測與分析；遏制、根除與恢復；事件後活動

**Network data:** The data that’s transmitted between devices on a network  
**網絡數據：** 網絡中設備之間傳輸的數據

**Network protocol analyzer (packet sniffer):** A tool designed to capture and analyze data traffic within a network  
**網絡協議分析儀（封包嗅探器）：** 用於捕獲和分析網絡中數據流量的工具

**Network traffic:** The amount of data that moves across a network  
**網絡流量：** 在網絡中移動的數據量

**Network Interface Card (NIC):** Hardware that connects computers to a network  
**網絡介面卡 (NIC)：** 連接計算機到網絡的硬件

**Packet capture (p-cap):** A file containing data packets intercepted from an interface or network  
**封包捕獲 (p-cap)：** 包含從介面或網絡攔截的數據封包的文件

**Packet sniffing:** The practice of capturing and inspecting data packets across a network  
**封包嗅探：** 捕獲並檢查網絡中數據封包的做法

**Playbook:** A manual that provides details about any operational action  
**操作手冊：** 提供有關任何操作行動的詳細說明

**Root user (or superuser):** A user with elevated privileges to modify the system  
**root 用戶（或超級用戶）：** 具有提升權限來修改系統的用戶

**Sudo:** A command that temporarily grants elevated permissions to specific users  
**sudo：** 一個臨時授予特定用戶提升權限的命令

**tcpdump:** A command-line network protocol analyzer  
**tcpdump：** 一個命令行網絡協議分析儀

**Wireshark:** An open-source network protocol analyzer  
**Wireshark：** 一個開源的網絡協議分析儀
